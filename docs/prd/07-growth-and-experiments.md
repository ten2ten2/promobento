# GPT 获客与付费实验

## 1 首轮要验证什么

首轮验证的是陌生目标用户能否通过用途信息理解产品，用自己的素材完成预览，并为具体交付付费。两组同时招募和开放，以各自完整漏斗评估。

GPT 来源只是一类获客渠道，不是独立商业模式。ChatGPT 能访问页面、站长主动询问自己的网站、页面被索引、用户实际点击推荐和用户完成付款是不同事件，不能合并成“GPT 已带来收入”。

## 2 两个高意图用途入口

| 用户任务 | 页面承接 | 例子应展示什么 |
| --- | --- | --- |
| 有软件截图和录屏，要做上线或功能更新短片 | 软件推广页 | 同一实际功能的输入素材、分镜、横版与竖版成片 |
| 有课程或数字产品素材，要做招生或上新短片 | 课程数字产品推广页 | 封面、目录或交付物如何组织成宣传片，准确 CTA |

典型用户表达是“我有产品截图，如何做一个可以改字的 30 秒发布视频”“把课程目录和节选做成 Reels 和 YouTube 的推广片”。这些句子用于设计页面和测试理解，不宣称已有经过验证的关键词搜索量。

每个用途页必须有可公开播放样片、真实输入要求、输出规格、可改什么、价格、保留期、预计步骤和直接开始按钮。页面内容对应真实产品；未做的 URL 自动抓取、AI 配音、发布排期不能提前宣传。

首发品牌为 PromoBento；用途页、样片字幕、分镜说明、价格、帮助与发布说明均为英语，说明“English videos at launch”。两个用户入口并列，不因为先做英语就删除课程团队入口。多语言架构是开发能力，首发获客页不宣称已经支持多语言成片。

## 3 可被检索的基础实现

公开页面 SSR 输出主要正文，样片提供静态 poster、可访问 MP4、文字分镜和必要的说明。没有用户交互也能了解输入、输出与价格。配置 canonical、sitemap、语义标题、可见 FAQ 和准确的结构化数据；没有真实评分就不添加伪造 rating。

站点名称为 PromoBento，规范主域为 `https://promobento.com`，首发 HTML 为 `lang=en`、`dir=ltr`。每个实际英语页面使用自己的干净 canonical；UTM、主题或语言偏好参数不形成新的索引 URL。英语路径保留根路径，不为了未来多语言先复制 `/en/` 或建立空的 `/zh/` 页面。只在对应语言的真实页面发布后添加该语言 URL 与互相关联的 hreflang。主题不改变 URL、SEO 文案或公开样片。[Google 多语言站点说明](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

允许公开页面被 OAI-SearchBot 抓取，并避免在 Cloudflare 防护中无意挑战官方已公布来源；训练爬虫策略独立设置。OpenAI 官方说明 OAI-SearchBot 用于搜索，ChatGPT-User 是用户触发访问，后者不决定搜索收录。[OpenAI 爬虫说明](https://developers.openai.com/api/docs/bots)

登录后项目、上传、订单和审阅页面默认不收录，权限验证不能仅靠 robots.txt。`llms.txt` 可作为帮助索引的补充文档，但不作为被推荐或排名的保证，不为它延迟产品闭环。

## 4 来源与事件模型

每个事件记录 `event_id`、UTC 时间、session/user/workspace/project、`audience_type`、入口页、任务、模板、时长、平台组合、ui_locale、video_language 和环境。theme_preference 与 resolved_theme 可作为界面体验分析维度，不作为定价或人群资格条件。涉及价格时附 SKU 与实验版本，事件不包含客户完整文本、私有媒体 URL 或支付敏感数据。

获客来源分别保留首触、最近非直接来源和可选自报答案。识别实际 ChatGPT referrer 或可信 UTM，不把全部 direct 访问归为 GPT。无法归因记 unknown；自报“来自 ChatGPT”与有技术引荐证据分开分析。浏览器或跨站支付丢失来源时，通过支付前已保存的本地订单关联，不在结账后猜测。

| 事件 | 触发定义 | 可信来源 |
| --- | --- | --- |
| `landing_viewed` | 人类会话打开用途页 | 客户端与服务端去重 |
| `signup_completed` | OAuth 验证成功并建会话 | 服务端 |
| `project_created` | 项目成功写入 | 服务端 |
| `assets_ready` | 至少一个合法规范化视觉素材可用 | 服务端 |
| `facts_confirmed` | 当前事实集由成员确认 | 服务端 |
| `storyboard_ready` | 有效分镜交付或手动完成 | 服务端，区分 AI/manual |
| `own_preview_played` | 播放自己的素材与当前 revision，至少 3 秒 | 客户端，需合法项目 |
| `own_preview_completed` | 同一完整版本累计播放至少 90% | 客户端 |
| `checkout_started` | 本地订单和有效 Waffo session 建立 | 服务端 |
| `payment_confirmed` | 验签或权威对账，首次成功入账 | 服务端，不采样 |
| `export_release_ready` | 首次所选文件全部交付并消费一个版本 | 服务端，不采样 |
| `download_started` | 签发后实际文件传输开始 | 服务端，不等于用户已成功发布 |
| `refund_succeeded` | 实际退款确认 | 服务端，不采样 |
| `extra_pack_paid` | 追加包成功 | 服务端，和新项目复购分开 |
| `published_self_reported` | 用户主动反馈发布平台与可选链接 | 自报，不冒充平台观测 |

另记 AI 成功与失败、手动编辑类型、输出失败阶段、队列时长、渲染时长、成本和人工介入。内部、自测、赠送、关联人员、测试支付使用标记过滤，并保留查看原始数量的方式。

## 5 指标定义

| 指标 | 分子与分母 | 解释 |
| --- | --- | --- |
| 素材激活率 | assets_ready 的合格工作区 / 注册的合格工作区 | 发现素材门槛问题 |
| 个人预览率 | 播放个人预览的工作区 / assets_ready 工作区 | 发现生成和编辑阻力 |
| 预览到付费 | 首次项目包实付工作区 / 播放个人预览的合格工作区 | 第一笔直接收入的核心指标 |
| 入口到付费 | 实付工作区 / 该入口合格人类会话 | 与整体获客效率结合查看 |
| 付费交付成功率 | ready release / 合法有效素材的付费导出请求 | 自动重试后口径，另报首次成功率 |
| 退款率 | 已退款订单 / 确认付款订单 | 同时按金额报告，区分技术和购买原因 |
| 首次价值时间 | assets_ready 到 own_preview_played | 与注册、上传、人工填表时长分开 |
| 复购 | 30 天内另一新项目付款的工作区 / 已满观察窗首购工作区 | 与同项目追加包区分 |
| 单单贡献 | 订单净收入减可变交付、获客及支持成本 | 不是净利润，不忽略退款和失败成本 |

所有漏斗按两类首批人群、获客渠道、设备和模板分组。小样本阶段报告绝对人数与完整个案，不能只展示漂亮百分比。

## 6 首轮实验安排

### 实验一 两类用户能否独立做完

每组招募 10 个符合条件的团队，使用自己的素材，以相同 US$39 项目价开放产品。参与者知道收费，不能把免费代做的满意度等同于付费意愿。

观察他们是否理解素材要求、完成事实确认、得到自己的预览、修改关键细节、理解版本收费并付款。研究者可以回答使用问题；如需直接替客户修片，标为 assisted，不能计入无人工介入的自助完成率。

方向性门槛为每组至少 3 个独立团队产生非赠送真实付款，并实际交付。该门槛用于决定继续投资，不足以估计稳定市场转化率。任何一组失败先核查输入门槛和模板质量，不直接宣判整个人群不成立。

### 实验二 GPT 引荐是否带来任务完成

两个用途页同时开放检索并保留来源。内部提示词测试只检查页面是否能被理解和准确描述，标记 internal。真实引荐流量必须由陌生会话进入，再关联素材激活与付款。

在获得足够真实访问前，不以不存在的 GPT 流量优化价格结论；可继续用直接招募验证产品付费。没有固定日期承诺“上线几天必有 GPT 订单”。

### 实验三 定价与重复使用

先维持两组同价与同权益。若预览满意但结账流失集中在价格，再进行有清晰版本记录的定价测试，例如后续 US$29 与 US$39；每个人群内部进行相同分配，不能让人群和价格同时混杂。已创建 Waffo session 保持其价格快照。

关注是否有人为下一次功能更新、下一期招生或新数字产品购买新项目；同项目 US$12 追加是编辑需求，不能直接当作月度订阅意愿。订阅功能以真实重复购买和更新频率为依据。

## 7 成本模型与护栏

单项目实际可变成本为：支付成功与失败费用，加退款与提现分摊，加 AI、素材规范化、最多三个成片版本及其多构图文件、存储、归档、下载和人工支持。

US$39 的订单按 Waffo 当前卡支付公开基础费率粗算，单笔成功支付费约 US$2.02；这不是全部交易成本。若内部把完整项目可变计算与存储预算暂设 US$6、客服预算 US$4，在不含税款、退款、提现分摊和获客的简化情景下，剩余约 US$26.98。此为算式示例，不能当作已测得毛利。[Waffo 详细费用](https://docs.waffo.ai/mor/fees)

实际收集每个处理 job 的资源用量与账单。初始目标为 US$39 项目包在全部包含额度被正常使用时仍有正贡献；不能只测用户导出一次就假定三个版本成本相同。追加包按 US$12 单独测算。

建议试运营全站可变计算预算软阈值 US$20/天、暂停新免费操作阈值 US$30/天，两者为运营可调初值。已经收款的交付有单独预留和人工处置通道；预算阈值不能让付费客户无期限等待。付费项目素材、版本和重试上限共同约束异常成本。

## 8 决策规则

如果两组都能独立完成并出现真实付费，继续优化平台构图和可重复模板，再验证新项目复购。如果某组创建多、预览少，先修输入和制作流程；预览多、付费少，检查质量、价格表达和替代工具；付款多但交付或退款差，优先修渲染与支付，不扩获客。

当前已有相近产品提供 URL 转视频和单次付费。宣传中避免“全球首个”或无证据的效果提升。对客户真正有价值的差异应通过可编辑事实、真实素材和完整交付体现。
