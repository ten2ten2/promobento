## 1 素材与作品

测试素材覆盖：横屏软件截图/录屏/Logo/两卖点；竖屏 App/长名/重音；课程封面/目录/节选/报价/日期；无价格、评价、收益数据的数字产品。边界包括损坏编码、旋转、超大像素、不支持格式、超长旁白、CJK/RTL/组合字符/缺字、多个工作区和恶意提示。虚构品牌明确标注，素材有使用权。

两类用户、15/30 秒、四构图覆盖连续运镜、蒙太奇、混合及复杂 Canvas 作品；分类只为回归，不是创作风格白名单。WebGL 等能力通过08的执行准入后再加入对应样例。同一素材至少制作两种镜头、构图或节奏明显不同的方案，并包含 Agent 自写的新镜头。静态图、空 JSON、固定六镜头演示均不能代替自由创作验收。

## 3 QA、冻结与完整输出

按[14 QA 规则](14-production-contracts.md#8-事实与qa授权)分别验证 Q0/Q1 的冻结资格、Q2 的完整成片检查，以及 BLOCK/REVIEW/INFO 的处理。`qualityEligibility:ready` 不能被界面误报为完整视频已交付；不可检查的内容不能记为通过。用户和运营样本复核美学质量，不强制每单后台人工审批。

按 03 与冻结平台配置逐文件运行 ffprobe，验证编码、尺寸、帧数/时长、音轨、体积、旋转及音画误差。实际像素无意外黑尾/闪帧，音轨无意外静音/削波，关键字和焦点在安全区。颜色修改不无故改变音轨，节奏修改重新对齐。

内部验收指标：视频帧数必须准确；MP4 容器时长与目标时长偏差 ≤2 帧，音画有效播放结尾差 ≤100 ms；母带及最终AAC解码后均按平台预设的 `loudnessTarget`（当前 −14 LUFS，允许±0.5 LU）、真峰值 ≤−1 dBTP，关键音效与画面对齐误差 ≤1 帧。这些是产品验收目标，实测结果随作品记录。

在08规定的实际 Renderer 环境中验证原生取帧、颜色转换和重复seek。音频检查源越界、实际混音字节、采样长度、静音和AAC编码前导/尾部，按有效播放区间检查总长，不把填充采样当新增内容；同一录屏的音画使用一致切点。新增渲染能力须有自己的媒体、时间和费用验收，不能沿用旧执行器结果。

适用的 AI 标记、受众披露及其实际文件证据验收按 09/14 执行；metadata 或映射文件存在不代表视频/封面已合规。采用 C2PA 等方案时，验证签名/完整性、检测与目标平台实际处理后的限制，缺覆盖不得记 pass。

演练首次批次部分成功、重复发布、补目标和 ZIP 失败，确认下载权限与版本消费遵守[14 交付规则](14-production-contracts.md#4-snapshotrelease与账务身份)。再停止 consumer、容器和 dispatcher，验证 outbox/租约恢复、重试上限、D1/R2 引用与队列重放；只针对实际创建和已售任务验收恢复，不将内部评测对象当作客户权益。

各制作阶段、排队与交付的分位数、失败和费用按下方性能关口实测，成本归因及30天贡献统一按[07](07-growth-and-experiments.md)；未标定值为 null，不将完成样片者的转化率冒充全部付费试用的转化率。

产品交互目标：普通参数本地更新p95≤300ms、LCP p75≤2.5s；支付inbox响应10秒／权益推进60秒。完成率目标95%须同时报告样本数与人工介入，小量工程自测不等于市场表现。


### 渲染与导演性能目标

区分**用户端到端耗时**（提交到可播放／可交付，含排队、冷启动、传输、必要QA与失败重试）和**执行服务耗时**（成功准入到实际文件/检查完成，不含排队）。下表创作/改稿项目标是端到端 p50（完整候选另有 p95）；原生取帧、低清生成、最终片及构图项目标是**空队列执行服务 p50**。每项必须另报端到端 p50/p95/p99、排队时长和失败分布，不能用服务耗时冒充用户等待。

| 环节 | 目标 |
| --- | --- |
| 开始创作至三张真实方向卡 | p50≤2分钟 |
| 选方向至可播放原生草稿 | p50≤3分钟 |
| 选方向至完整候选，含创作、审片、成片与QA | p50≤10分钟；p95≤18分钟 |
| 定点改稿至候选 | p50≤3分钟 |
| 已准备工程的原生取帧 | p50≤3秒 |
| 30秒低清全片**生成到可播放** | p50≤30秒；正常速度真人审阅另计，不把观看时间藏入生成耗时 |
| 纯2D最终片 | 30秒片p50≤60秒；15秒片p50≤45秒 |
| WebGL最终片 | 帧占比≤30%时p50≤180秒；整片3D p50≤300秒 |
| 准备四画幅，纯2D | p50≤3分钟 |

完整产品构图另有空队列执行服务 p95：单30秒≤5分钟、常用三构图批次≤12分钟，从实例准备到必要检查完成。不同容器规格和复杂度独立统计；硬期限用于止损，不能替代性能达标。

### 真实高并发、内存和经济性关口

按[04 §3](04-architecture-and-data.md#3-队列资源与隔离)的**持久排队、事件驱动准入、独立容器和流式处理**进行负载验收。S1/G1 用相同冻结工程、同样QA和固定镜像对照，负载覆盖：

| 批次 | 必测场景 | 不得省略 |
| --- | --- | --- |
| 1、4 个同时提交 | 15/30秒，2D/复杂 Canvas/WebGL，预览和最终片；冷/热缓存、不同资源档 | 无队列与有队列基线，实际CPU/内存峰值、画质、声音、成本 |
| 16 个同时提交 | 单租户与多租户混合，免费/已付款同队列，资源阶梯、重复投递 | admission公平、付费容量保护、排队超时与租约回收 |
| 64 个同时提交 | 突发、持续积压、取消、实例崩溃/OOM、Workflow 重启、延迟R2/D1、恢复 | 背压、自动补漏、收敛时间、没有重复生成/收费、最终账本准确 |

上述数字是**同时提交的操作数**，不是同时运行64台容器；实际运行上限取部署配额与实测容量。全场景分开记录 queueWait、admissionDelay、coldStart、render、finalEncode、upload、QA、totalWall、attempts、成功率、队列最大年龄与积压清空时间。统计 p50/p95/p99、样本数、失败/超时/人工介入，未测量记 `unverified`，不能从单个成功任务推导。付费任务不得被免费突发饿死；超过已配置等待预算必须给出可恢复的明确状态，不能排队直到执行期限过期。

内存与资源证据须同时有**实例对应的 Cloudflare Containers CPU/内存/磁盘指标**和可取得的容器/Chromium/FFmpeg 进程明细（RSS/PSS、cgroup 使用量、FD、临时盘与 OOM/exit reason）；平台未暴露的细项标 null 并说明，不能把父进程 RSS 误写成进程树峰值。每档报峰值、p95/p99及持续占用，拟定额原则为正常负载 p95 峰值≤该档已分配内存的80%、负载矩阵中无OOM；该余量为**待实测校准的验收目标**，不得代替平台硬上限。缺关键容器内存观测、未知实例归属或任何未解释的 OOM，都阻断 G1/发布，不能再次豁免为 `unverified`。

正确性要求：零跨租户缓存/任务、零重复 release/额度消费/费用结算、零已取消任务晚到提交、零幽灵租约和零未经确认停止即重用容量；QA/ffprobe/实际音画不因快取或资源分级降级。付费履约必须在获准的队列/操作总期限内成功，或留下可恢复/补偿的明确终态；不足容量时限流新免费任务，不能悄悄挪用已售履约容量。队列等待不得占用物理容器；空槽通知优先、定期兜底不得变成毫秒级轮询。

优化项分别做**可回退、同作品 A/B 基准**：预览专用低清原生捕获、内部预检帧与最终回看去重、直接使用符合平台预设的原生视频流以避免第二次整片 H.264 转码（必要时只处理音频）、有界视频 PTS 派生缓存、FFmpeg 线程及1/2 Chromium取帧并行、不同容器规格。记录成功文件成本、vCPU活动时间、预留GB·s/磁盘、R2/D1、冷启动与质量差异；只有真实编码、音频响度/峰值、动态QA、确定性seek和取消恢复一致才可采用优化，不能以“减少步骤”代替检查。

单位成本目标取[agent-policy.unitCostTargets](../../config/agent-policy.json)。模型、计算、预留/未知、缓存读取、失败/重试和共享费用分开呈现，按[07](07-growth-and-experiments.md#4-完整单位经济)核算完整操作和每份合格产物；不拿单文件编码价代替创作、目标准备或付费履约成本。队列等待预算、类别配额和资源规格在启用新云任务前须形成**非空、可验证的部署策略**，数值由实测确定，不在本文臆设平台容量。G1 的执行与证据出口只在[08](08-codex-execution.md#2-里程碑与退出关口)维护。
