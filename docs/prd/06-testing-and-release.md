# 测试与发布验收

## 1 验收原则

P0 的完成标准是两个首批人群都能使用自己的真实素材，独立完成创建、修改、预览、Waffo 付款和多平台下载。界面截图、mock 支付或本地一段样片不能替代完整链路。

测试优先覆盖金钱、数据隔离、不可变内容、格式兼容及恢复能力。纯展示文案不要求建立镜像实现的单元测试；每项测试应能捕获明确错误。不要用只断言自身 mock 的测试作为外部集成已完成的证明。

## 2 固定验收素材集

| 数据集 | 内容 | 验证目的 |
| --- | --- | --- |
| 软件 A | 3 张宽屏界面截图、1 段 20 秒录屏、Logo、2 个功能卖点、试用 CTA | 核心产品发布闭环 |
| 软件 B | 竖版 App 录屏、长英文产品名、带重音字符的专名、功能更新 | 竖屏素材、英语排版与专名字形边界 |
| 内容 A | 课程封面、课程目录、1 段节选、真实交付物描述、价格、报名日 | 课程招生闭环 |
| 内容 B | 模板截图、演示录屏、无价格、无评价、无效果数据 | 缺失事实不补造 |
| 边界集 | 损坏文件、异常旋转、超大尺寸、HEVC、超长旁白、极长标题、网络中断 | 输入与错误恢复 |
| 隔离集 | 两个不同工作区、Owner 与 Editor、过期分享 token | 多租户和权限 |

可使用虚构演示产品，但数据集要明确标为测试内容并拥有素材权利。不得借真实品牌编造效果、订单或客户评价。

## 4 格式和渲染验收

三种结构 × 两种样式 × 四种构图，分别用软件与内容样例生成 30 秒版本，共 48 个基本场景组合；15 秒至少每种结构和构图覆盖一次。此矩阵针对模板排版差异，不需要对每个微小字段做重复渲染。

| ID | 测试 | 必须结果 |
| --- | --- | --- |
| AC-15 | 六个平台导出 | 对应尺寸与命名正确，Instagram 可选方形可用 |
| AC-16 | ffprobe 全量校验 | MP4、H.264、yuv420p、30 fps、预期宽高和音频参数 |
| AC-17 | 15 秒及 30 秒 | 450 或 900 帧，容器时长误差不超过 2 帧 |
| AC-18 | 录屏与旁白混合 | 音视频结尾差不超过 100 ms，无多余黑帧或音频爆音 |
| AC-19 | 关键文字和焦点边界 | 在产品规定安全区内；越界时能定位场景 |
| AC-20 | 重复生成同一指纹 | 同一内容与配置复用，不产生重复收费；内容结果稳定 |
| AC-21 | 原始上传对象被覆盖 | 已确认素材和已付款快照仍引用不可变副本 |
| AC-22 | 重启或杀掉渲染容器 | 状态能恢复，旧 generation 不能覆盖新结果 |
| AC-23 | 一个构图失败 | 只重试失败项；未完成首次批次不开放中间文件 |
| AC-24 | 目标平台实际上传 | 有权测试账号接受文件；记录文件 hash、入口及日期 |

实际平台上传测试包括 TikTok、Instagram 当前自然上传入口、X 普通账号、YouTube 横版与 Shorts。内容审核、账号资格和编码问题分别归因。没有测试账号时仍完成 ffprobe 与构图验收，预设标“推荐格式”；不能虚构实际发布通过记录。

## 5 Waffo 与账务验收

| ID | 场景 | 必须结果 |
| --- | --- | --- |
| PAY-01 | 成功购买项目包 | 一份 order、一份 grant、3 个版本；首次交付后剩 2 个 |
| PAY-02 | 付款时继续编辑 | 自动导出已确认快照，最新修改保留在草稿 |
| PAY-03 | 同一回调发送 20 次 | 只授予一次、不重复入业务导出、不重复消费 |
| PAY-04 | 回调与返回页同时对账 | 收敛到同一支付与权益结果 |
| PAY-05 | 伪造签名或篡改 raw body | 不发权益，有安全事件且不泄露敏感信息 |
| PAY-06 | 合法延迟重试签名 | 按 Waffo 时间单位和窗口接受，仍业务去重 |
| PAY-07 | 测试事件发到生产地址 | 不授予生产权益 |
| PAY-08 | 未付款而直接打开成功 URL | 显示未确认，不导出付费文件 |
| PAY-09 | 关闭收银台或不点 Done | 页面恢复后可查状态，已确认付款仍后台处理 |
| PAY-10 | 重复点击购买及网络超时 | 复用活动订单和幂等键，避免重复收费 |
| PAY-11 | 过期状态后收到权威成功 | 正确恢复，不能丢掉已付费交易 |
| PAY-12 | 只剩 1 个额度并发请求两个不同快照 | 最多一个成功预留，余额不为负 |
| PAY-13 | 同一快照并发导出三个平台 | 仅一个版本额度，正确聚合文件 |
| PAY-14 | 成片首次整批最终失败 | 释放预留；重试不新增订单 |
| PAY-15 | 同一已交付版本补平台 | 不再次消费版本，新文件来自原四构图快照 |
| PAY-16 | 订单与 outbox 写入后发送队列失败 | dispatcher 恢复，没有钱已收任务永远丢失的状态 |
| PAY-17 | 追加包在项目第 89 天付款 | 增加 3 个版本，保留期变为新付款后 90 天 |
| PAY-18 | 退款请求处理中、成功、失败 | 界面和权益与实际状态一致，不提前标已到账 |
| PAY-19 | 金额含税、币种错误、字段单位 | 正确匹配权威报价，拒绝或复核不匹配交易 |
| PAY-20 | 系统意外重复初始购买 | 有可查重复付款处置，退款请求同样幂等 |
| PAY-21 | 只买追加包 | 新增 3 个版本，不自动消费、不产生渲染任务 |
| PAY-22 | A 稿订单未付，编辑成 B 稿后再购买 | 确认界面、实际订单与输出引用同一快照，不静默复用旧稿 |
| PAY-23 | 退款冻结与最后一个文件完成同时发生 | 只有规则允许的一方先提交；退款后的旧作业不能公开文件 |
| PAY-24 | 最新追加已确认，再到达旧购买回调 | 项目正常截止不倒退；退款最新追加后按有效购买正确重算 |
| PAY-25 | 初始包退款时有有效追加包 | 明细与独立退款状态可查，不遗留已付费却不可用的权益 |
| PAY-26 | 首批渲染期间持续补平台 | 初始目标清单不变，首次只消费一次，后补平台独立处理 |

在 Waffo test mode 运行完整集成；在启用生产前按商户允许方式完成小额真实支付及退款验证，并确认实际 webhook 环境、账目和交付。真实测试由项目方执行和留档，本 PRD 不代表已经执行。

## 6 安全与删除验收

跨用户与跨工作区逐项尝试访问 project、asset、export、order、job、share；猜 ID、改变请求 workspace_id 不能扩大权限。过期下载链接、撤销分享、移除成员、退出登录之后的权限均由服务端重新确认。

恶意文件、超大像素、异常编码及 FFmpeg 资源耗尽必须在有上限的容器处理，不导致全站排队失控。尝试在文本中注入脚本或模型指令，不应执行代码、调用任意外链或改变付款规则。

过期清理测试覆盖免费项目、正常付费项目、追加包、退款、共享素材引用和清理过程并发付款。用户删除媒体后，普通日志、公开 CDN 和审阅入口不能继续暴露内容。

## 7 性能与容量预算

以下是待目标环境测量的工程验收目标，达不到时先调资源、模板和并发，再决定公开承诺。不要从上游作者 Mac 的渲染速度直接推导云端 SLA。

| 指标 | 初始目标与测量条件 |
| --- | --- |
| 公开页 LCP | 目标 p75 ≤2.5 秒，记录实际设备与网络 |
| 普通编辑到画面更新 | 素材已就绪时 p95 ≤300 ms |
| 分镜生成 | 有效文本任务 p95 ≤45 秒，失败可手动继续 |
| 素材就绪到首个个人预览 | 排除人工填表与上传，p95 ≤60 秒 |
| 单个 30 秒构图编码 | 空队列时 p95 ≤5 分钟，包括容器启动 |
| 常用三构图整批交付 | 空队列时目标 p95 ≤12 分钟；排队时间单列 |
| 支付回调确认 | inbox 持久化并应答在 10 秒内，权益推进目标 60 秒内 |
| 付费导出成功率 | 有效素材自动重试后 ≥95%，报告样本量 |

一个渲染 job 处理一个唯一构图和编码指纹，单次 10 分钟超时；release 聚合多个 job。ZIP 在文件完成后作为派生任务处理。这样任务运行预算不会随用户一次选择六个平台而无限增长。

先用真实容器对 10 个串行和 4 个并发样本测资源、速度、故障恢复与单次成本。只为解决明确风险扩测，不盲目追求覆盖数字。

## 8 环境与发布门槛

本地使用 mise、Cloudflare Vite 和官方本地绑定模拟；容器用本地 Docker。预发布环境使用真实 Cloudflare 测试资源和 Waffo test mode。生产拥有独立资源与密钥，不能通过更换页面域名把测试账务混入生产。

发布前必须有：两类完整样片；P0 功能验收；四构图渲染与六预设配置；Waffo 完整支付对账退款；素材私有与额度并发测试；域名及支持渠道；来源和许可清单；真实 Cloudflare 容器运行记录；可恢复备份与故障开关。

本次新增的上线门槛：

- PromoBento / promobento.com 在页面、SEO、分享页、配置和实际外部应用资料中一致；不覆盖客户品牌与客户 CTA。
- 域名取得、DNS/TLS、Google OAuth 往返、Waffo 域名验证与回调、支持渠道分别有实际结果；域名查询记录不能替代任何一项。
- 两类首发流程的界面标签、帮助、政策、错误和下载说明均为英语；未开放的网站语言没有入口、空 URL 或 sitemap 条目。用户文案可自由混排，不属于网站翻译资源或语言上线名单。
- Light / Dark 下主要页面、表单、焦点和错误可读；System 跟随系统；慢网/延迟 JS 时首屏无错误主题闪烁，无 hydration 警告。
- 两个浏览器的不同主题与账户内容不因 CDN 缓存互相串用；预发布和正式 Cookie 为各自 host-only。
- 改界面主题不会改变 revision、内容指纹、视频关键帧、额度或订单；Waffo 首次会话的英语与 darkMode 设置符合 05，切主题仍复用原活动订单。

种子色彩可以做静态对比度校验，但不能用 JSON 检查替代成品页面、视频上传或真实支付验收。

外部缺少商户资料或平台测试账号时，开发和其他验收继续。功能可以留在预发布或明确推荐状态，但不能宣称生产收款或实际平台发布已经完成。

## 9 发布与回滚

配置与数据库迁移采用先扩展、后切换、再清理策略。新模板和 renderer 先进入预发布，运行固定素材关键帧回归，通过后仅用于新快照；已有快照继续固定原版本。

发布设置独立开关：新注册、免费 AI、新 checkout、新渲染作业。出现故障优先暂停新成本，保留订单查询、已购权益、既有文件下载与退款通道。已经收款的任务进入可恢复队列，不通过关闭全站让用户丢失查询能力。

回滚到上一 Worker 与 renderer 镜像，保持消息和数据 schema 的兼容；不能为回滚删除生产订单。版本化 renderer 应用与资源由注册表路由，老项目仍能执行它冻结的版本。额外验收：创建 renderer V1 的 release，部署 V2，再为 V1 补平台并故障重试，确认实际运行的仍是 V1。D1 恢复、R2 文件引用恢复与队列重放需在预发布完成一次演练并记录结果。

重试恢复还需验收：已写失败 attempt 和重试 outbox、尚未送出消息时杀掉 consumer，dispatcher 仍能推进，且实际执行最多 3 次；不能因为 ack 丢掉后续触发。

## 10 交付证据

每次里程碑交付提供执行命令、环境、结果、样片链接或文件、剩余失败项。证明至少包括测试输出、ffprobe JSON、四构图关键帧、订单和额度账本的脱敏记录、容器故障恢复结果与费用样本。

完成报告需明确哪些是本地测试、测试支付、真实生产付款或实际平台上传。没有运行的项目不能用“验证通过”代替待验证状态。
