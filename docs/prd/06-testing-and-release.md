两类用户、15/30 秒、四构图覆盖连续运镜、蒙太奇、混合及复杂 Canvas 作品；分类只为回归，不是创作风格白名单。WebGL 等能力通过08的执行准入后再加入对应样例。同一素材至少制作两种镜头、构图或节奏明显不同的方案，并包含 Agent 自写的新镜头。静态图、空 JSON、固定六镜头演示均不能代替自由创作验收。

## 3 QA、冻结与完整输出

按[14 QA 规则](14-production-contracts.md#8-事实与qa授权)分别验证 Q0/Q1 的冻结资格、Q2 的完整成片检查，以及 BLOCK/REVIEW/INFO 的处理。`qualityEligibility:ready` 不能被界面误报为完整视频已交付；不可检查的内容不能记为通过。用户和运营样本复核美学质量，不强制每单后台人工审批。

按 03 与冻结平台配置逐文件运行 ffprobe，验证编码、尺寸、帧数/时长、音轨、体积、旋转及音画误差。实际像素无意外黑尾/闪帧，音轨无意外静音/削波，关键字和焦点在安全区。颜色修改不无故改变音轨，节奏修改重新对齐。

内部验收指标：视频帧数必须准确；MP4 容器时长与目标时长偏差 ≤2 帧，音画有效播放结尾差 ≤100 ms；母带及最终AAC解码后均按平台预设的 `loudnessTarget`（当前 −14 LUFS，允许±0.5 LU）、真峰值 ≤−1 dBTP，关键音效与画面对齐误差 ≤1 帧。这些是产品验收目标，实测结果随作品记录。

在08规定的实际 Renderer 环境中验证帧就绪、颜色转换和重复seek；启用motion4/8前另验子帧合成及超时。音频检查源越界、实际混音字节、采样长度、静音和AAC编码前导/尾部，按有效播放区间检查总长，不把填充采样当新增内容；同一录屏的音画使用一致切点。字段与身份规则按14。

适用的 AI 标记、受众披露及其实际文件证据验收按 09/14 执行；metadata 或映射文件存在不代表视频/封面已合规。采用 C2PA 等方案时，验证签名/完整性、检测与目标平台实际处理后的限制，缺覆盖不得记 pass。

演练首次批次部分成功、重复发布、补目标和 ZIP 失败，确认下载权限与版本消费遵守[14 交付规则](14-production-contracts.md#4-snapshotrelease与账务身份)。再停止 consumer、容器和 dispatcher，验证 outbox/租约恢复及重试上限。预发布至少做一次 D1/R2 引用恢复和队列重放，并确认新版部署后旧快照仍能重试和补目标。

### 证据保存

普通语法、文档链接、JSON 和参考测试结果写提交说明或 CI，不为每次修改创建日记。真实 Cloudflare 隔离/回收、正常速度视听、模型/成本基准、邮件送达、收款退款和平台上传等难复现、仍支持当前能力声明的结果，才在 `docs/evidence/` 建独立报告。

报告记录 commit、环境、实际命令、镜像/资源/模型版本、输入/输出 hash、目标/时长/runId、检查范围、ffprobe/帧/音频/费用及失败复现，明确失败和未运行项。受限源码验收另保留实际imageId/sourceTreeHash、capabilityProfile、策略版本、qaInputHash、隔离实测与回收结果；`productionEligible:false`不能转换为生产放行。真实样片与可重现渲染报告保存为CI artifact或受控对象引用，不把每轮媒体文件提交Git。占位、mock和本地参考不标生产通过；短期URL、验证码、密钥、客户源码/素材全文不进入公开日志。私有原始证据使用受控引用，保留和删除按04。
