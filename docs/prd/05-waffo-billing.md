# Waffo 支付与权益

本章是商品、订单、退款及成片使用权的唯一细则。创作操作计量由 [14](14-production-contracts.md) 补充，不能覆盖本章购买保障；素材许可审核与法律依据见 [09](09-sources-and-decisions.md)。真实收款需通过商户、域名、签名、订单查询和收款退款验收。

## 1 商品和购买意图

P0 使用 Waffo Pancake，一次性按项目购买，无自动续费、提现余额或跨项目通用充值。其签约 MoR 法律实体是向买家销售的法律销售方，按实际合同处理交易税费、收据及付款；PromoBento 经营主体负责产品服务与履约。不能把 MoR 仅称为支付代理，或据此免除平台的内容、隐私与服务责任。结账和收据展示实际销售方与服务方，依据 [Waffo MoR 说明](https://docs.waffo.ai/mor/what-is-mor)及已签合同核实，查证日 2026-10-20。

目录币种 USD；实际支付方式取商户已开通能力。四个 SKU 是当前唯一目录，服务端拒绝目录外商品，不接受其他商品名、协议别名或客户端定义权益。

| SKU | 目录价 | 条件 | 授予当前项目 |
| --- | --- | --- | --- |
| `single_export` | US$19 | 未有在途/有效初始购买；已有确认且全部合法目标就绪的快照 | 当前已确认作品的全部七个合法目标、高清无 PromoBento 品牌水印、1 个成片版本；新增整片、AI 改稿和素材重处理预算均为 0 |
| `project_pack` | US$39 | 未有在途/有效初始购买；可先买创作权益再导入/生成 | 新增 3 个成片版本、5 次整片创作、15 轮 AI 改稿、20 段及 1,200 秒素材处理预算 |
| `project_upgrade` | US$20 | 本项目有有效 `single_export` 初始购买，且该初始购买没有在途/有效升级 | 只补差额：新增 2 个成片版本、5 次整片创作、15 轮 AI 改稿、20 段及 1,200 秒素材处理预算；不重置原账本 |
| `extra_pack` | US$12 | 本项目有有效 `project_pack` 或有效 `project_upgrade`，且未清理 | 新增 3 个成片版本、2 次整片创作、10 轮 AI 改稿、20 段及 1,200 秒素材处理预算 |

19 美元买的是当前确认的成片，不赠送购买后的新创作；相同 `contentHash` 补平台、重下和系统修复仍免费。用户改变实际内容后导出需有新版本余额；仅有 19 美元初始权益的项目先升级，不能买追加包绕过升级。39 美元的 5 次整片是付款后新增创作机会，已有免费样片转入不扣这 5 次；从样片首次导出仍消费 3 个版本中的 1 个。19 加 20 美元累计基准权益与直接购买 39 美元相同，已消费版本、历史操作、仍未用试用次数与其他有效 grant 原样保留，不能再完整授予一次 3 个版本。同一有效 `single_export` 初始购买最多有一个在途/有效升级；升级及其全部子追加全额退款成功、且不存在未知付款或未结算退款后，才释放有效升级槽，允许新建订单重新升级。历史订单、消费和费用不得因退款或新购改写；旧付款及幂等去重标识不随活动槽重置，不能再次授予。记录和个人信息按 [04](04-architecture-and-data.md) 的目的与期限保留，不以不可变账本为由无限保存客户内容。初始 19/39 购买及其全部依赖同样结清后可创建新的初始订单；任何时刻同项目在途/有效初始购买合计最多一个。

Checkout API 明确提交 `purchaseIntent`，持久化为 `purchase_intent`。`single_export` 固定 `purchase_and_export`；39/20/12 的 UI 默认 `top_up_only`，也可由用户明确选择 `purchase_and_export`。`top_up_only` 禁止带 `snapshotId`，只授予权益，不准备构图、不建导出预留或编码任务；因此无试用额度的新项目也能先买 39 美元创作权益。所有 `purchase_and_export` 都必须带已确认 snapshot，全部合法目标的可执行来源、事实及 QA 先冻结，付款只启动所选目标的编码。`project_upgrade` 必须带 `upgradeFromOrderId`，其他 SKU 禁止该字段。test/production 商品 ID、商户和密钥分离。

四种实际成功付款均将正常截止更新为仍有效购买中最大成功付款时间加 90 天，延迟回调不得使日期倒退；升级和追加延长同项目全部剩余额度的使用期，退款按有效购买重算。`access_expires_at` 与 `media_delete_after` 分开，正常到期后 7 天只读宽限。免费项目宽限内，已有仍有效的全目标确认快照可买 19 美元导出恢复；没有有效快照或要继续创作，先买 39 美元 `top_up_only` 恢复。仅有 19 美元初始权益且符合升级资格的项目可用 20 美元升级恢复，已有完整创作资格的项目可用 12 美元追加恢复。宽限不得启动有成本的素材、构图准备或 QA 来补齐/更新快照，失效快照必须先购买创作权益恢复；已有完整有效快照才可选择同时导出。已清理项目关闭购买恢复入口。

### 1.1 一次试用及空草稿

免费试用按内部 `user_id` 终身累计一次，只原子绑定一个 trial project：1 次成功整片、2 轮成功 AI 改稿、需要比较方向时同一次创作内的 3 张方向卡，成片导出版本为 0。创建项目显式提交 `requestTrial`，默认 false；仅工作区 Owner 可用自己的 `user_id` 领取。领取和项目创建在同一事务完成；同用户并发创建最多一个领取成功。未申请或已领取仍可创建空 draft，返回明确的无试用状态，引导购买 `project_pack` 的 `top_up_only`，不能暗中赠送或调模型。

改变工作区、登录方式、Owner、成员、项目复制或删除均不重置领取记录；身份关联保留领取历史。成员共同使用已绑定项目的同一份额度，不按成员各送一次；未用次数只留原项目，付款既不清零也不再发放。免费项目创建后正常 7 天、只读宽限 7 天；没有试用或有效购买的草稿可读已授权的不可变素材引用、编辑普通文本元数据，但不得上传、素材处理、方向生成、AI 创作、云预览或目标准备。复制不搬移其他项目的处理/创作额度，也不以内容哈希绕过素材权限。

免费范围不包含可下载成片。普通文字/颜色/已声明变量的本地编辑不限；云端素材处理、QA、预览和目标准备各有独立硬预算与去重，不能把每次输入都变成无限云端作业。已有 19 美元购买不会新增这些创作权益；原试用尚未用完的次数仍可在原项目正常期使用，导出新内容前应明确显示须升级及所需版本。

### 1.2 素材处理计量

试用累计最多处理 12 个唯一视觉素材（其中录屏最多 3 段、合计 180 秒）、Logo 1 个、旁白 1 条及配乐 1 条；两条音频各不超过 60 秒。因此有时长媒体总共最多 5 段、300 秒，全部唯一处理输入累计最多 200 MiB。所有上限同时满足；视觉素材不是只检查当前列表长度，删除或替换不返还累计数量/字节。图片、录屏与音频仍须符合 [输入配置](../../config/input-capabilities.json) 的格式、单文件尺寸/时长及项目同时保留限制。

39/20/12 每次购买各增加 20 段、1,200 秒有时长媒体处理权益，录屏、旁白和配乐均计入；19 不增加素材重处理额度。处理权益是累计预算，不放宽当前输入数量/大小限制；付费图片、其他无时长素材处理、云预览及 QA 同时受每 operation 上限和账号/项目通用滚动费用预算控制，成功操作也累计，不能只限制失败或单次调用。按项目、输入字节哈希、处理版本和规范化处理参数查重，已获授权的相同处理结果缓存命中不重复消费；用户换文件或主动改变处理版本/参数按实际新操作计量，不能把同文件的任意重处理都冒充缓存命中。处理成功交付可用资产时消费素材权益；系统失败释放用户预留，但费用及失败累计数不回滚。系统缺陷修复不另扣用户额度，仍记真实成本并受系统预算控制。

### 1.3 成片使用权与内容归属

免费预览仅供项目内制作、授权审阅与评估，不授予对外发布、广告投放或商业成片使用权。有效付款并正式交付的成片，用户就平台有权许可的部分取得全球、持续有效、非独占的商用许可，可发布、投放、剪辑、配字幕，并交给代理商或委托客户用于相应业务，无需署名 PromoBento。项目删除、额度到期或云端副本清理不终止已合法取得的成片使用权；退款及拒付的例外按 §8。

| 对象 | 权利边界 |
| --- | --- |
| 客户素材、文案、事实、项目变量与修改内容 | 用户及原许可方保留既有权利；上传不证明用户拥有所有权，工程格式和存储位置不改变内容归属 |
| 平台背景技术、通用模板及音画组件 | 各权利人保留权利；平台授予成片内使用、修改及商业传播所需的嵌入许可，不交付独立运行库或素材库再销售权 |
| 项目专属新增表达 | 仅平台确实拥有、专为本项目新增且依法可转让的权利随有效付款交付转让，交付记录明确范围；排除客户内容、通用组件与第三方权利，不凭条款创造不存在的版权 |

用户素材的原许可、肖像/声音同意和渠道、期限、署名等限制仍须履行；不满足选定发布用途时须替换素材或取得补充授权，付款不能解除限制。平台默认选材应支持上述商用范围且无需成片内署名，具体准入见09。不允许独立转售平台组件的限制不剥夺客户自有内容或其依法独立取得的权利。P0 不交付工程源码；不提供源码导出不等于平台取得客户变量或文案的权利。

通用风格、方法及组件不独占，其他客户可能得到相似风格；平台不得因此复用客户私有内容。AI 或程序化制作不当然排除人类原创表达的版权，也不保证整个成片可登记、排他或无第三方权利；美国版权依据和适用范围见09。条款版本、成片及订单关联随交付记录保留，不能只凭当前套餐名称判断既有许可。

## 2 内容身份、快照与消费

收费身份为 `UNIQUE(project_id, content_hash)` 的 release，**不是 snapshotId 或 revisionId**。`contentHash` 算法以 14 与参考测试为准；同内容恢复、重新 QA、重排目标记录顺序、仅修改非渲染 styleLabel 不产生新消费。新请求若内容已存在且原交付授权仍有效，返回原 release 及原购买快照，不用当前草稿重新装配已购文件；请求键相同但 body 不同仍按幂等协议返回 409。

窄边界：某 release 已发布并消费版本，之后因技术原因获退款且其对应 grant 已撤销时，同 `contentHash` 的云端交付授权不能凭旧文件、旧消费收据或新付款自动恢复。在建立该内容的 `purchase_and_export` checkout 前返回 `RELEASE_RESTORATION_REVIEW_REQUIRED`，进入 `review_required` 人工恢复处理，不自动收第二笔款或恢复下载。人工须先明确恢复交付及与原退款、新购买权益相关的账务安排，保留原始收据/消费/退款记录；不能套用普通同内容去重，让新 grant 看似完全未用却已再次得到交付。此处处理继续下载和云端服务，不推定既有成片商用许可终止或已转让版权回转；法律效果按 §1.3、§8 的记录判断。未使用退款、未发布失败 release 的退款，以及全链结清后购买新内容或 `top_up_only` 先购创作，仍按正常购买和退款规则执行。

snapshot 是不可变的确认收据，保存完整 Composition、事实证明、全部合法 target 的来源、依赖、音轨、封面、规则和 renderer。新 snapshot 可指向同一内容身份而不产生第二次扣费。只有改变实际内容指纹并导出才消费新版本；不用 AI 相似度判断收费，也不以“换了宣传主题”为由拒绝合法项目编辑。

提交新内容导出时原子预留 1 个版本，固定 `initialTargetIds` 和初批文件清单；每个所选目标有 video、cover、mapping 三种逻辑产物。全部通过编码和内容 QA，且 reservation 有效、grant 未冻结、项目未删除，才原子写 ready、consume、published_at 并开放下载。等价逻辑文件可复用物理对象，ZIP 随后派生，不决定消费时点。

部分失败只重试失败文件；首次完整发布前不下载零散结果。最终失败释放预留，同 release 重试可新建 reservation，但 consume 按 release 唯一。每个 reservation 的释放幂等，同 release 同时最多一个有效预留。队列重复投递不增加消费。

补平台只运行该 snapshot 已冻结来源，不调用 Agent，不扩大首次清单、不新预留或消费，不把已交付 release 退回未交付。补平台失败保留原文件并免费恢复。重新下载、ZIP、授权刷新和系统运行缺陷修复均不另收成片版本。

## 3 独立状态

| 实体 | 当前状态值 | 边界 |
| --- | --- | --- |
| 订单 | created / checkout_open / awaiting_confirmation / paid / expired / canceled / review_required | 提供方付款事实不能被旧 pending 消息降级 |
| 退款 | requested / processing / succeeded / failed | 申请成功不等于资金已退回 |
| 导出 release | reserved / rendering / ready / failed / cancelled | 与 exportManifest Schema 同名；snapshot 单独保存，不是 release 状态 |
| 权益预留 | reserved / consumed / released | 唯一操作与审计，不靠 paid 布尔值代替 |

订单的 `canceled` 和创作/导出的 `cancelled` 属于各自当前协议，不混用序列化字段。付款返回页只读取权威状态；用户关页不取消已付交付。

## 5 创建 checkout

1. 验 Owner、项目可恢复、SKU 条件及显式 `purchaseIntent`；服务器根据可信目录取金额、币种、权益、保存期和提供方商品。请求不接收客户端金额、币种、权益或返回 URL。升级从 `upgradeFromOrderId` 核对同项目有效 19 美元付款、未退款/冻结、没有在途/有效升级或未结清的升级链；追加重查有效创作购买资格。需要导出时校验事实和全部 target 来源/QA，缺项返回 VARIANTS_NOT_READY，不创建 checkout；另检查 §2 已发布后授权撤销的同内容恢复，命中时返回 RELEASE_RESTORATION_REVIEW_REQUIRED，不创建自动购买会话。只增权益允许尚无素材或 revision 的 draft。
2. 展示实际销售方、购买内容、价格、税费、权益增量、正常截止、清理日期，以及成片许可、适用素材限制和退款摘要；链接完整条款，记录接受的版本和必要同意，不用云端保存期充当成片许可期限。`purchase_and_export` 额外展示不可变 snapshot、七个目标的真实静态缩略图、封面、时长和首次编码目标，并可切换到每个目标基于冻结来源的真实预览。静态图只辅助检查构图，不能替代动态时序、字体、音轨和事实 QA，也不能用主画幅截图假装其他目标已通过检查；宽限内只播放仍有效的已有预览，不启动新准备或 QA。`top_up_only` 明确只增加额度，不显示虚构已确认成片、不预留版本。已购权益和已取得许可不被后续调价追溯缩减。
3. Billing DO 与 D1 先原子 get-or-create 购买活动槽，再请求提供方。19/39 共享同项目初始购买槽，不能各按 SKU 并发开一笔初始订单；在途/有效升级槽按初始购买 ID 唯一，追加按本项目有效创作资格和活动订单仲裁。已付链全额退款结清并排除未知付款/未结算退款才可释放对应槽；未付款订单须权威确认外部已不可支付且无未知付款，不能只凭本地过期释放。保存意图、价格/权益/政策版本、币种、商品 ID、项目、所需 snapshot、升级或追加依赖订单 ID，不能先并发创建多个可付订单；新购买使用新订单/付款标识，付款去重约束不随活动槽释放而删除。
4. SKU、意图、依赖及 snapshot 一致才无提示复用；不一致显示原订单和内容，让用户明确继续。创建另一会话前确认原会话不可支付，或安全过期并对账；本地 canceled 不证明外部不能收钱。相同请求幂等键但摘要不同仍返回 409，不重用旧键更新购买内容。
5. 服务端 Merchant API Key 请求携带业务订单号和受控 metadata，不以浏览器 Store Slug 模式替代需要的服务端字段。持久化高熵幂等键和请求体，未知结果只用同键重试/查询，不能马上另建订单。
6. successUrl 取可信 appUrl 与 `/app/billing/orders/{localOrderId}`，正式为 promobento.com；ID 服务端生成。会话 1,800 秒是内部策略，不使用任意 Host/前端 origin。
7. 新会话 language=en，darkMode 仅取合法 resolvedTheme，未知默认 Light。已存在会话和未知结果重试请求体不因主题切换改变，更不能因此重复创建订单。

提供方返回行为按实测适配：当前设计不依赖 cancelUrl 或取消 webhook；买家未点击 Done、关页、支付拒绝或 session 过期都由本地状态及权威查询处理。付款期间编辑另存草稿，交付读取原 snapshot，不用新封面冒充原购买内容。

## 6 签名、金额与事件核验

提供方适配需验证出站 RSA-SHA256/秒级时间戳、入站原始 body 与 X-Waffo-Signature/毫秒时间戳及签名覆盖格式。参考协议给出的 45 分钟重试容忍窗口不能替代业务去重；实施测试用原始字节及官方测试向量锁定，不能混淆两种时间单位。

限制 body 大小，验签，核对环境/store/事件，可靠写 inbox+outbox 后再 2xx（内部目标 10 秒）；数据库失败返回可重试错误。Inbox 唯一键为 environment/store/eventType/eventId，订单及 provider payment ID 另有唯一约束，不同包装事件也不能重复授予。测试事件不能授予生产权益。

order.completed 核对本地订单、provider 商品、币种、价格快照、付款 ID；不匹配进入 review_required，不按付款邮箱猜用户。金额是整数最小单位，提供方 display-format 字符串等明确转换，不用浮点。目录、税额、渠道实付、商户净结算分别保存；不强行要求含税实付等于目录 1,900/3,900/2,000/1,200 美分。

价格页说明税费由 checkout 展示；商户明确含税/另税分类。P0 不自行优惠、换汇或接受前端价格覆盖。金额/币种/商品不一致人工核查，不能静默改账。

## 7 原子授予、对账和迟到付款

确认付款后，单一事务标 paid、记录不可变购买收据、授予唯一 grant、更新期限及处理 inbox；收据保存实际 SKU、价格/税费、权益增量、依赖关系、意图、快照与条款版本。`purchase_and_export` 同事务创建导出 intent+outbox，`top_up_only` 不产生导出。版本、创作、改稿、素材处理预留/消费分别关联授予来源，不靠“当前方案名”反复覆盖总余额。升级只追加差额 grant，保留原始 19 美元收据和已消费记录；即使其 1 个版本已用，升级仍只加 2 个版本。任一步失败可识别恢复，不留已核验付款无对应授予或待核查记录。回调、返回页、Cron 并发收敛到一份 grant/首次导出；发送失败由 outbox 补发，渲染失败不改写付款事实。

返回页查询提供方同订单最多每 15 秒一次；Cron 每 5 分钟扫描，24 小时仍未知转人工核查，不当作提供方交易终止。授予前重查初始/有效升级槽、历史付款去重、依赖订单与项目墓碑：迟到付款不能借槽释放叠加第二份初始或升级权益。两笔误重复初始/升级成功付款，核实后原路退款多余一笔，不自动转成其他商品或重复 grant；同一提供方付款重复回调只返回原记录，包括已经退款的旧付款。依赖退款或项目已删除/清理时的迟到付款先记真实事实，进入 review_required，协调恢复或原路退款，不能复活墓碑或虚构可导出内容。对完整快照的购买不得以重新上传生成一支新片冒充原交付；恢复须保留原确认内容，否则由 Owner 选择新项目另行处理或退款。

## 8 退款与权益仲裁

### 8.1 受理政策与提供方窗口

常规自愿整笔退款为付款 7 天内且该订单授予的成片版本、整片创作、AI 改稿及素材处理权益均未消费。不能把“还没有导出”当成“没有使用”；仅预留但未交付可用结果不算消费。已消费权益的退款转人工核查。系统持续无法交付、重复扣款及法定救济另行受理；失败尝试的系统费用不能成为拒绝交付保障的理由，已交付技术缺陷先免费修复，无法修复再按事实退款。

[Waffo 退款说明](https://docs.waffo.ai/features/refunds)和[具体工单 API](https://docs.waffo.ai/api-reference/endpoints/refunds/create-refund-ticket)在 2026-10-20 查证时规定一次性付款的 14 日工单窗口，可审核拒绝或部分批准；这是提供方受理/执行条件，不等于本产品 7 日自愿政策或统一的法定无理由退款权。第 8–14 日的申请及 Waffo Portal 工单仍按理由、合同和适用法律处理。超过 API 窗口的法定救济或履约退款转 MoR 人工协调，真实收款前验证该路径；不以 API 拒绝代替法律判断，也不虚构可用的超窗自动接口。

适用消费者保护法时保留不可排除的撤回、瑕疵和其他救济。对欧盟消费者即时交付数字内容，按实际交易类型取得开始履行的明确同意、失去撤回权的确认及必要的合同确认；“已下载”或接受普通服务条款本身不能替代这些前提，瑕疵救济也不因此消失。职业/商业购买不能未经判断套用消费者身份。依据：[欧盟撤回权](https://europa.eu/youreurope/citizens/consumers/shopping/returns/index_en.htm)、[数字内容保障](https://europa.eu/youreurope/citizens/consumers/shopping/guarantees/index_en.htm)，查证日 2026-10-20。

### 8.2 冻结、依赖与资金执行

用户提交退款申请，核验后用唯一 refundTicketMerchantExternalId 和原币种 display-format requestedAmount.amount 发起；processing 期间不能声称到账，成功由真实事件或权威对账确认。商户提交的字段和初始 processing 状态按本节具体 API 适配，锁定版本并以真实账户验证。

退款接受、创作/素材成功消费和首次交付经同一 Billing DO/事务仲裁。冻结相关 grant 的 available/reserved，暂停其创作提交与发布；冻结先发生则晚到 worker 不消费/发布，消费先发生按实际使用政策判断。退款失败对仍有效、项目未删除/未过期的授权解除冻结，恢复仍可用的原 reservation/release，不绕过当前权限和 generation；成功撤销该 grant 未用权益并取消相关预留。消费优先使用本项目仍可用的试用 grant，再按有效购买成功时间顺序分配付费 grant，记录每次预留和消费的确切来源；不把已经消费的额度移到另一订单以制造未用退款条件。供应商费用及失败预算不因用户额度释放、退款或补偿而清零。

客户 P0 申请整笔退款，部分退款、已消费额度和依赖链的例外由管理员按真实交易明确处理，不按模糊比例自动退款。每笔升级记录其初始 19 美元订单，每笔追加记录支撑它的 39 美元或 20 美元订单；有效升级必须连同其初始购买有效，追加资格按整条依赖核验。

| 申请退回的购买 | 必须检查的后续订单 | 成功后的边界 |
| --- | --- | --- |
| `single_export` | 依赖它的升级及该升级下全部追加 | 不能只撤销初始资格而留下失去使用资格的已付升级/追加 |
| `project_pack` | 依赖它的全部追加 | 依赖款项妥善结清后才撤销基础创作资格 |
| `project_upgrade` | 依赖该升级的全部追加 | 原有效 19 美元收据/权益保留；升级增量撤销，整条退款链结清后可释放有效升级槽，历史记录和旧付款去重不清零 |
| `extra_pack` | 本单对应的预留、消费及输出 | 只处理本单，不冻结无关购买或已有合法输出 |

退款前列出完整关联订单、金额、不可再用权益及已交付成片的处理，Owner 明确确认范围；存在已用或无法自动退款的依赖即进入人工处理，不先退基础款。满足条件的链按追加、升级、初始购买的顺序各自用独立幂等退款单执行，确认子单已成功退款才发起父单；提供方调用不能假装具有跨订单事务。任一步失败保留成功退款的事实，停止后续基础退款并核查，未退款订单不能被误标退款或静默丢弃权益。异常外部退款/争议使依赖提前失效时先冻结相关在途作业、记录 review_required，明确安排依赖退款或经 Owner 同意的恢复方案，不能让迟到 worker 继续发放内容。

没有有效购买才回到原试用/无权益状态，试用领取和已用次数不重置；退款失败不等于购买失效。期限按仍有效且依赖成立的购买重算；因退款缩短期限的自动媒体清理不早于通知后 7 天，也不早于其他有效购买正常截止加宽限；用户主动删除仍按04执行。告知期只允许查看/按政策下载，不恢复已撤销编辑/AI/导出。退款回调不立即销毁媒体；不可变购买/退款收据、依赖关系、账本与失败成本继续保留，财务审计可按权限查询。保留文件不等于保留云端下载授权；已发布后因退款撤销云端交付的同内容重新购买按 §2 人工恢复边界处理。

### 8.3 已交付成片与拒付

服务额度、云端交付权限、成片商用许可及已转让权利分开处理。账本 grant 的 frozen/revoked 状态不能自动回转版权，系统也不能收回用户已下载文件。

| 情形 | 成片与服务的处理 |
| --- | --- |
| 未用额度退款、部分退款或服务补偿 | 撤销明确退回的未用权益；默认保留已合法取得的成片商用许可，不波及无关订单和输出 |
| 升级或追加退款 | 按依赖链结清服务权益；不因子订单退款撤销其他有效购买对应的成片使用权 |
| 已交付订单异常全额退款 | 人工明确关联订单/输出、是否保留成片许可及处理依据；终止继续使用须有有效条款或约定并遵守强制法，已转让权利另行处理，不能由 grant 状态代替 |
| 拒付调查中／最终结果 | 调查中可冻结相关未结算服务，不能当作最终退款；胜诉按仍有效权限恢复，最终失款再按交易和条款处理对应服务与许可，不跨订单追溯 |

授权处置关联原订单、release、条款版本、资金结果及通知记录；没有明确合法处置依据时，不自动终止既有成片商用许可或宣称权利回转。已确认依法不再享有许可的成片须停止后续使用；云端权限执行与法定退款救济不能混为一项。Waffo 争议结果和期限以[官方拒付流程](https://docs.waffo.ai/mor/chargebacks)及实际商户通知核验。

## 10 创作次数与履约保障

整片创作与 AI 改稿先预留，可用候选交付时分别消费一次；一次提交的一组批注计一轮，接受不重复消费。未交付的失败/取消释放用户预留，交付后审美拒绝不返次，已证实技术缺陷可幂等补偿。方向、作曲、构建和内部修复不拆成新收费操作；同内容目标准备不消耗成功次数。字段、批注限制、操作预算和计量算法统一见 [14](14-production-contracts.md#6-ai操作费用与成功次数)。

价格与预算未实测标定时保持关闭。接单前须证明预算和容量能够覆盖已售权益，并预留已付交付资源；其他调用不能耗尽该预留。超限保存工作、停止新增非预留调用，已收款任务按预留恢复；持续无法履约按本章处理，不能要求用户额外付款解除系统预算。退用户次数或退款不抹掉真实费用，也不允许无限重试。

付款后补平台只运行冻结来源。系统缺陷修复以独立 correction 关联原 release，免费且保留原收据和输出；身份、证据更新和产物规则按 14。参考测试不构成真实交付证明。
