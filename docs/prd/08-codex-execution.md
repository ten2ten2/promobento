# 实施顺序与交付

先读 [AGENTS](../../AGENTS.md)、[PRD 索引](README.md)、01/03/05/10/12/13/14。目标是可运营产品，文档、参考页面和返回成功的空脚本不能替代实现。本章是里程碑与开发顺序的唯一来源。

## 1 里程碑

| 阶段 | 实施内容 | 退出条件 |
| --- | --- | --- |
| M0a 本地自由创作 | GSAP-free 绝对时间运行时与 huashu-motion 本地基线对照；Director/Treatment、原创镜头、关键帧、ABC/SFX、字幕、MP4/QA | 15/30 秒、两类素材、独立盲审发布意愿、确定性与单位经济门槛；有实际费用/失败证据 |
| M0b Cloudflare 准入 | 同源包在目标实例验证构建/workerd、实际字形、PTS 抽帧、冷/顺/逆向 seek、WebGL、子帧成本/回收隔离；并行最小 Google/邮箱/Waffo test | 2–4 vCPU 与全局容器预算下的真实结果；无账户保持 NOT_TESTED，本地通过不能替代 |
| M1 Studio 与用户流程 | 登录后一次账号试用、无试用草稿先购入口、上传事实、创意、隔离预览、多批注一轮、候选patch、CAS/恢复、声音、合法目标、移动UI | 两类用户能自助创建、购买、修改与恢复；混排、网站主题和实际音轨可用 |
| M2 可靠交付 | 完整Schema/权限、D1试用与订单唯一性、运行/成本账本/预算/队列、全目标冻结、四SKU与两种购买意图、Waffo权益与延迟编码 | 编码、消费、增量升级、补目标、退款依赖链、删除和版本化运行恢复实测 |
| M3 团队与运营 | 邀请、审阅、冲突、清理、成本/归因/质量面板与用途页 | 权限隔离、真实完整任务和可解释费用漏斗 |
| M4 生产上线 | 性能、安全、平台上传、收款退款、域名发信与回滚 | 06/12 外部门槛有真实结果，不虚构通过 |

**M0a 质量与成本准入：** 先用 2 个有授权的题目完成端到端冒烟，再完成 6 个题目（软件 3、课程/数字产品 3）× 15/30 秒的 12 组同条件对照。每组在相同素材、模型候选与费用上限下分别以固定上游 huashu-motion 本地 GSAP 基线和 PromoBento GSAP-free 管线制作，必要时各做一轮范围相当的改稿；基线仅限隔离研究，不打包/上线。盲审至少由不参与制作的目标用户按「愿意公开发布」评价，记录人数和偏差；M0a 暂定退出门槛为 PromoBento 至少 8/12 组获认可，且认可率不低于基线。该小样本是工程准入而非市场转化率证明，任何质量未达标都不得以测试数代替。

**M0a 成本准入：** 每题同时记录模型输入/输出与提示缓存命中、生成/修复/局部改稿、素材/字幕/音轨、单目标与四种构图、七个合法target的准备及Q0/Q1、内部错误/重试、CPU/容器/存储等实际费用和耗时。以账号一次1整片/2轮试用及$19/$39/$20/$12各自新增权益估算用满成本；按07分别做q=5%/10%/20%的敏感性分析并纳入A/D/E，不将本地研究样本称为真实转化率或已盈利。模型价格版本、美元与token硬上限仍为null且执行关闭；只有同等质量、全部费用与预算上界经实测，才能提出配置变更。响应式优先并记录每新增构图的边际费用；购买并导出前完成目标来源，不以收款后新调用模型掩盖准备成本。

M0a 也必须使用隔离测试素材与运行环境；M0b 未通过可继续无生产数据研究，不开放客户任意代码或收款承诺。基础认证、计量和权限必须在相应功能对用户开放前完成，不以表格阶段为理由延后安全。

### 四阶段与三道关口

下表归纳同一组M0a–M4里程碑，不新增并行项目或重复进度来源。当前实际完成范围仍见实施进度。

| 阶段 | 对应工作 | 下一步的证据关口 |
| --- | --- | --- |
| 1 规格收敛 | 当前产品、目录、Schema、状态与参考页面一致；清除失效别名与重复规则 | 静态检查通过后开展研究，不据此开放真实服务 |
| 2 质量与运行验证 | M0a与M0b；真实作品、费用账本和云隔离 | G1：上述12组质量门槛、确定性/资源回收实测通过，完成含免费队列情景的成本报告并标定可执行上限 |
| 3 完整自助交付 | M1–M3；身份、试用、四商品、云制作、可靠交付及运营 | G2：06的真实集成、并发/重放/退款/删除与恢复验收通过，费用可对账，方可进入M4外部上线验证 |
| 4 有限付费试运营 | M4外部条件全部通过后，按07招募两类真实任务用户 | G3：两类各至少3个独立非赠送付费交付；成熟30天队列扣除剩余权益预计履约成本后，满足事前确定的贡献目标与最大试用损失预算，且作品质量和可靠性达标，才扩大获客 |

每次试运营开始前冻结质量/贡献目标、样本窗口、费用上限和止损条件并记录负责人；没有基于实测的预算不收款开启模型。G1/G2不要求伪造尚不存在的市场数据，G3不能用小样本实收、问卷报价或增量利润替代完整经济核算。关口失败时在对应阶段修复、缩小受影响范围或停止新增成本；查询、退款、既有下载和已收款任务恢复仍保留。

## 2 代码与权威来源

应用责任划分为 web、api、jobs、agent-runner、renderer。按实际实现建立 packages：contracts、composition-runtime、creative-director、audio-engine、quality-engine、agent-orchestrator、platform-presets、billing、auth、db、ui、i18n、brand；不建空目录凑模块数，不擅自更换云或数据库。

project_revisions 为唯一版本，routes 为 URI 注册来源，agent-api 绑定 Schema，production.schema 定义传输结构，14 定义状态/hash/引用/计量，12 定义认证例外。候选与示例是正常工程输入，不代表运行成功；生产边界拒绝 exampleOnly。购买 snapshot、内容 identity 和首次交付集合不能混为一谈。

## 3 工具和当前命令

mise 管工具与任务，pnpm 冻结锁文件；部署支持→依赖兼容→兼容范围内正式版→精确锁定→目标实测。正常安装复现锁文件，不因文档修改升级工具。具体见 [依赖策略](../dependency-policy.md)。

| 命令 | 实际范围 |
| --- | --- |
| `mise run install` | pnpm 冻结安装 |
| `mise run check:repo` | 全部当前文档、引用、配置、路由、认证、主题与契约一致性 |
| `mise run check:contracts` | 正式 Schema 样例、语义/hash/合法目标和 API 清单 |
| `mise run test:contracts` | 协议反例、CAS、计量、状态与内容身份参考测试 |
| `mise run build:agent-reference` | 从当前模板、tokens、预设、四商品、试用与改稿限制生成离线Studio参考 |
| `mise run check:agent-reference` | 参考同步性、合法目标和样例边界 |

应用 dev/build/test:e2e/test:render/test:billing/test:auth/check:i18n/test:appearance/deploy/smoke 在真实实现时加入，不能用空脚本。Node 备用环境可运行兼容检查，但须报告版本，不能冒充固定 mise/Node/pnpm 验证。静态、实际 D1/浏览器/云、真实模型、邮件、支付和平台上传分别测试。

## 4 环境和交付

可信 appUrl、回调、发信与支持地址来自 brand/routes/auth；不从任意 Host/前端 origin 拼接。D1/R2/Queues/DLQ/DO/AI/EMAIL 以及新增计算类别同样受全局预算；Google/OTP/CSRF/Waffo/服务间和模型密钥只给可信 Worker，沙箱不带凭据。未配置真实模型、价格和预算则关闭执行。

完成报告列变更、真实命令/环境、成功与失败、未实现 P0、样片、费用、恢复及外部账户条件。进度仅在真实状态变化更新；普通检查记录在提交/CI，重要验收按证据规则。交付必须包括真实迁移、锁文件、部署运维、许可、安全与健康/回滚，不以规格完整声称产品可运行。

提交直接快进 remote main，推送前检查 expected head，不强推覆盖他人提交；清理工作树中的失效文档不等于改写 Git 提交历史或删除用户作品/财务版本数据。
