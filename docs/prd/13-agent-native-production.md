# AI 导演、原生制作、素材与改稿

本章描述从素材到成片的导演与改稿方法。画面由 huashu-motion 原生工程执行，参考 Hypit 的制作方法；实际进度见[实施状态](../implementation-status.md)。

## 1 原则：先导演，再写画面

先理解产品和真实素材，再决定开场、卖点、视觉关系、阅读节奏、声音与 CTA。可以使用 HTML、SVG、GSAP、Canvas、Three.js、WebGL、图表或录屏，不限制镜头数与风格；模板只用于加快起步。

- 真实素材优先：产品截图、录屏、Logo、课程封面、实物/人物音视频和已确认事实。缺证据时可用明确标为“概念表达”的抽象动画，但不能捏造界面功能、评价或成绩。
- 电影时间只有一条：15 或 30 秒，30 fps，450/900 个整数帧。原生页面与最终音轨遵从同一时间；平台构图分别完成，不拉伸或隐藏关键事实。
- 看得见的选择：方向卡必须来自实际工程关键帧；最难镜头要用真实字体/素材验证；导演不能用空 JSON、文字计划或生成模型自述代替画面。
- 同一个事实只保留一个权威来源；用户最新明确要求优先。参考作品里的秒数、人物和台词不是新作品不可变的事实。
- 原生 HTML/JS 是**唯一可执行的画面源码**。Brief、Treatment、Script、参考分析和素材决策是导演与编辑的元数据，不准另建第二套会渲染画面的 Scene DSL。

## 2 引擎和导演方法

- **huashu-motion** 执行原生 HTML/JS、动画、声音、逐帧捕获和 FFmpeg 整片导出；不再建立第二套视频执行语言。
- **Brief、Treatment、Script** 分开管理事实、导演意图和正式台词。参考片的可见证据、语义时间、素材候选和锁定用于指导原生工程，不直接渲染画面。
- **P0** 包括真实素材、方向选择、原生制作、批注、版本和结果复用；自动转写、生成图/视频/TTS 和精细语义轨道作为 **P1** 单独验收，不扩展为完整非线性剪辑器（NLE）。

方法来源见[NOTICE](../../packages/methods/NOTICE.md)，服务权限、交易和版本规则见 04/05/14。

## 3 项目内容的唯一归属

| 内容 | 保存什么 | 谁能修改 | 不能保存什么 |
| --- | --- | --- | --- |
| Brief | 目标、受众、任务、已确认事实、必要原文、CTA、品牌、参考、平台、预算/选择 | 用户确认；可信宿主记录变更 | 导演猜测、随意扩写事实、实现细节 |
| Reference Analysis | 每部参考的完整叙事、注意力变化、系统角色、观察与解释的区分 | 分析工具与用户纠正 | 新片自己的台词或时间线 |
| Reference Timeline | 源片时间码、代表帧、字幕/声音、进入/持续/退出、证据片段 | 分析工具/人工复核 | 把源秒数当目标时间 |
| Treatment | 创意主张、Hook/转折/回报、节奏、阅读位置、镜头工作、视觉连续性、声音落点和最难镜头 | 导演与用户选择 | 重复一整份最终台词或可执行伪代码 |
| Script | 采用的口播/字幕文本、说话角色、显示/发音差异、语义 Segment/Selection/Moment 标识 | 用户可审阅；修改触发关联检查 | 参考秒数、生成 prompt、复制的台词版本 |
| Materials | 原始/规范化/生成媒体、用途、来源、真实 SHA、候选、接受与锁定状态 | 用户选择/可信材料服务 | 临时 URL 作为唯一资源身份 |
| Native Project | 每画幅入口 HTML、JS/CSS、vendor、图形/声源引用和声明变量 | 隔离原生作者与受版本校验的改稿 | 第二套图像执行 DSL、凭据、跨租户数据 |
| Result / Review | 输入版本、实际源码和音轨、输出媒体、报告、人工审片、可复用候选 | 可信执行、审核和有权限的用户 | “应该成功”的模型自述代替产物 |

正式台词在 Script 维护；Brief 保存必须准确的短语，Treatment 保存导演意图。原生字幕、旁白和变量只是 Script 的投影。项目来源、评论、候选和结果按 workspace/project 持久保存并恢复，不靠聊天上下文猜测。

事实改动更新 Brief，故事和镜头改动更新 Treatment，台词改动更新 Script；画面细节和素材调整落实到原生代码及资产引用。

## 4 参考片：从观察到新作品

P0 允许把用户上传视频标记为 Reference。将参考按完整作品和局部证据两个尺度阅读，先核验实际时长、帧率、画面和音频可读性；不依赖自动搜索/下载站外素材。P1 可增加受控 URL 取得与自动转写。参考不计作作品中可显示的素材，除非用户另明确选用对应片段。

分析结果至少包含：

1. **整体**：开头为什么让人停下、主张如何推进、反差/笑点/揭示在哪里、高潮和 CTA 如何完成；哪些视觉/声音系统从头贯穿。
2. **时间码**：对应源片时窗的关键帧、出场对象、上屏文字/口播、构图层级、进入/持续/退出、相机和音效；密集变化时使用短间隔连续帧而不是四张缩略图。
3. **证据分级**：画面实见、音频实听/转写、自动推断、导演解释四类明确标记；不凭截图推断不可见的真实功能或人物身份。
4. **要继承的关系**：例如某词出现时替换图卡、关键问题后切出产品操作、音效与产品状态变化同时出现。用户可指定保留、改变或舍弃。
5. **目标映射**：新片自己的产品、台词、人物/声音、材质、镜头、画幅与平台 CTA；从语义关系重新安排 15/30 秒，必要时删减段落，不把长参考片机械倍速。

一部参考可以支持多个作品；一个作品也可取多个参考的不同导演关系。每个被采用的关系指向来源证据，避免把观察、理解、实现混成一个“参考 prompt”。分析失败时保留可人工审阅的抽帧和具体缺口，不声称已理解整片。

## 5 导演制作流程及交付物

| 步骤 | 导演要完成什么 | 可验收结果 |
| --- | --- | --- |
| A 读懂材料 | 整理事实、品牌、产品演示、声音、参考、缺口及限制 | Brief、素材清单、参考证据 |
| B 找到表达 | 确定一个主要观众认识、视觉主角、Hook、揭示、CTA、主要视觉语言 | 三方向真实关键帧或直接制作的明确方向 |
| C 设计全片 | 写完整 Treatment：beat map、能量反差、阅读停留、音效点、原生技术、跨画幅焦点 | 覆盖 15/30 秒的节奏与四个代表位置 |
| D 规划材料 | 为每段定义来源和角色：真实截图/录屏、图形、A/B-roll、字幕、独立文字、声音 | 需要制作/复用/生成的素材及依赖 |
| E 验最难镜头 | 先用实际目标尺寸、素材、字体实现高风险机制 | 可执行原生关键镜头 + 实际取帧 |
| F 完成原生工程 | 写 HTML/JS 与全时间线，完成转场、持续状态、音效与混音 | 完整可 seek 的主画幅工程与直接低清捕获/播放 |
| G 分目标构图 | 在同一叙事/事实下重排 16:9、9:16、4:5、1:1 | 各目标独立来源版本、安全区检查 |
| H 质量检查 | 读源码、看帧、看完整运动、听声音、核最终文件；必要时有预算地修复 | 可复现报告、清楚的失败或候选状态 |
| I 用户反馈 | 时间/对象批注、局部补丁、对照、接受/拒绝 | 新原生版本和可恢复的前后结果 |

方向卡只在目标不明确时要求三选一，且同一创作计一次；已有明确方案不强迫选择。选择方向绑定真实生成文件摘要，用户等待期间不会被自动选为 Fit。Treatment 不由 renderer 执行为第二条 timeline。

Hook 要与产品有关，画面从一开始便有具体的观看目的；节奏允许沉默、停留、硬切、连续变形或快速蒙太奇，不以“每两秒一镜头”作固定规则。先画主视觉与相机落点，再从实际阅读区反推细节。一个抽象点可以贯穿影片，但没有叙事必要时不强制加入 mascot 或常驻 hero。

## 6 素材导演、生成与可复用候选

所有素材按**创作角色**而非文件扩展名分类：

- **A-roll / performance**：承载话语或实际行动的主体，既可为用户录屏/口播，也可在未来使用经批准的生成视频；声音与表演媒体保持同步。
- **B-roll / evidence**：为事实、对比或情绪提供可观察的画面，能在主口播持续时覆盖画面；不是随意填空的库存素材。
- **Product demonstration**：实际截图和交互录屏优先，指出要看清的区域、输入、动作及结果；装饰包壳不能虚构产品功能。
- **Caption / Typography**：前者随口播/语义，后者是独立叙事文字；避免两层同时抢走阅读焦点。
- **MG / scene component / effect**：承担图表、卡片、比较、视觉解释、衔接和局部动作。组件边界来自共同行为，不因复用而把一次性镜头硬做公共包。
- **Audio**：用户原声、旁白、原生 ABC 音乐、音效与未来 TTS，明确谁在什么时段主导听觉。

每个材料节点记录用途、原始来源与 SHA、规范化版本、依赖它的画面/音频、候选集合、用户接受的候选、锁定范围、被替换原因和可复用 Result。生成任务另记模型/提示摘要、输入参考、参数、费用和回执。失败但已经成功产出的素材保留为未采用候选；重试前先查看是否可复用，不能因一次网络断开再次无意付费生成。

当需要延续某人、产品、空间、色彩或声音，先用**已经接受、最贴近当前镜头的真实图像/录音/生成输出**作为身份锚点。下一视角应明确相机方位、光线、眼神/物件关系，以及允许改变的东西；依赖保持浅而有用，避免无意义的“参考图→中间图→中间图→最终图”链。接受一幅新的关键图后，后续候选优先引用它，保证多镜头连续性。

素材锁定保护已确认候选；局部CTA/镜头改动只使真实依赖失效，不能重生成无关图片、声音或构图。复用依据实际字节与[04 §3缓存规则](04-architecture-and-data.md#流式媒体与安全缓存)，不依赖相似文件名或模型自述；全局品牌、身份、Script变化须列影响图并经用户确认预算。

P0 必须能使用用户上传的真实图/录屏和原生图形、声音。P1 可选接图像生成、参考图生成视频、文本生成视频、TTS/角色声音和媒体补片，按各自能力单独开关和验收；没有外部服务时仍能完成完整原生宣传片。P1 的人物、声音、场景、镜头连续性评审与实际生成费用独立记录，不能仅靠中间提示词“质量高”判断。真人/播客/UGC 复杂格式可延后到 P2。

## 7 Script、语义事件与绝对时间

Script 是最终台词和字幕的唯一权威。一个 **Segment** 是可表演的短段，Role 表示说话人，Display Text 保留应显示的拼写，Speech Text 在需要时说明读音（例如品牌缩写）。**Selection** 代表图形覆盖某段意思的区间；**Moment** 代表揭示、回答、状态改变或音效落点的语义事件。无声动画也可使用作者命名的 question/reveal/CTA，不强行创建语音事件。

这些名称是导演元数据，不是另一个渲染语法。可信时序解析把它们转换为**原生绝对时间**：开始帧、结束帧和必要的持续窗口；相同事件可同时驱动画面、字幕、相机和声音。每个窗口约束在 0 至 449/899 的合法整数帧，边界严格以实际 30 fps 计算。镜头可以重叠、留白或完全无口播，最终 timeline 只有一条 15/30 秒的明确结束点。

有实际口播时，时间来自同一媒体字节的真实转写/对齐证据（媒体 SHA、解码时长、语言、词/字符区间、可信产出版本）；允许用户校正文字与错误的词时间。只有该证据正确且段落映射明确，才能把“某个词出现”投射到当前成片的时间。用户换音轨、裁剪、调换段落或重写 Script 后，相关字幕、画面和音效投影失效并重新计算。

没有可靠对齐、或者 P0 未开放自动对齐时，创作者手工指定命名帧和停留窗口并清楚标注“作者定时”，不能把参考片秒数、估算语速或另一个音频的时间戳伪装为测量结果。过长口播先缩稿、分段或让用户改目标，不强制加速声音或延长影片。最终片头与片尾均不得因音轨长度被 FFmpeg 默默截断。

## 8 构图与原生组件

视觉先决定“观众看什么”和“画面如何把它说清”，再决定材质、特效与组件技术。真实演示的截图保持足够大；推拉镜头要说明要读的区域；临时出现的卡片要有入场、阅读、离场或持续状态。B-roll、字幕、演示主体和 CTA 可以共存，但同一时刻应有明确的视觉层级。

原生项目每个重要可编辑对象提供稳定 ID；DOM/SVG 用可定位的元素，Canvas/WebGL 用原生区域与命中信息。需要统一改动的对象可以组成原生 scene 组件；独立声轨/字幕/图卡仍可各有编辑入口。P0 只暴露真正稳定的原生变量、对象选中和批注；P1 可为组件补“Studio Companion”等价描述，定义时间轴 Item、Inspector 字段、选择对象和哪个源字段拥有这个编辑。不能让 Inspector 成为一份脱离源码的自由 JSON。

当前编辑不要求所有作品可拖拽所有对象、任意改时间或变成完整多轨剪辑软件。用户直接改值后，应可找到同一对象并预览；对时间/台词/事实有影响的编辑调用 AI 改稿并按时序与检查要求重算。未来拖动语义事件时修改该事件的来源声明，不对每个视觉组件单独写一套“挪几秒”的内部时间。

## 9 音乐、声音、字幕和真实视听

音乐与画面在 Treatment 阶段一起设计：BPM/能量/停顿/落点、ABC 或选定合法音源、音效、旁白、实际录屏声音和静音选项。原生 huashu 的合成器、采样、SFX 和混音承担 P0；可选择更符合不同产品性格的音色，不每条都套同一乐队/节拍模板。用户明确静音时不伪造空声道；无声观看仍看得懂主要信息和 CTA。

将音效绑定语义 Moment 或确定的帧事件；口播主导时音乐适当降低，画面换镜不应突然切断连续的说话声。真实录音的声轨按源 PTS 处理并与画面使用同一截取点，音效和动态变化到帧级。声音源或节奏变化时只重做依赖它的部分并复核最终混音；颜色/文字小改不应重复花费作曲费用。

字幕可以按段、词、角色或强调词出现；中英混排注意字形、换行、强调位置与安全区。未来自动对齐必须保留 Display/Speech 的关联，允许真实发音与品牌显示拼写不同。特定“随人头移动字幕”只在实际画面需要且可测量对象区域时实现，不因画面里有人就自动添加追踪。

验收包括最终解码音轨、响度、峰值、对齐与完整正常速度试听，目标值和采样要求统一见[06](06-testing-and-release.md)。频谱、音量数字或静帧均不能证明音乐好听、节奏舒服或旁白可懂。

## 10 Studio 批注、局部补丁与版本

用户可以按时间、画面坐标、对象 ID 或区域留下多条修改意见；提交的是同一修订基线的一轮批注。服务端核对同项目/workspace、baseRevision、画幅、整数帧、实际可命中的对象/区域与当前权限。未命中对象仍可记录位置和意见，但不能猜一行源码；前端不能把保存的批注换绑较新的版本。

原生修改以精确文本补丁或声明变量写入副本。每个查找必须唯一命中，全部修改和语法/取帧检验成功后才能形成新修订；失败保留旧源码、批注和用户输入。修改“第 8 秒推进改为环绕”必须落实到浏览器的镜头行为，并复查目标时窗、相邻转场与其他共享对象，不能仅改 Treatment 或审核文字。

候选必须有父版本、影响范围、实际工程和可播放证据。用户可 Accept、Reject、Undo/Redo、恢复检查点或比较多个候选；接受按 CAS 检查当前稿是否已经变化，冲突时保留双方而不是偷偷覆盖。已被拒绝/取消的候选不能恢复为可接受；成功次数与模型实际费用按 05/14 的独立账本处理。

一个被接受的素材/音乐/镜头可锁定以保护未来局部改稿。全局身份、事实或声画关系确实改变时，系统列出需要解除锁定或重新审核的依赖；不允许一个“只改字幕颜色”的操作静默更换所有镜头。项目新 revision、candidate、Result、元数据都保留可查询关系；旧的可用产物作为真实缓存，而不是不可恢复的短时生成 URL。

## 11 模型、成本、任务与可信边界

导演上下文只携带本阶段需要的事实、参考证据、Script/素材和真实版本；用户文本、网页与注释不能授予工具权限。模型/预算取[模型配置](../../config/model-providers.json)及[Agent 策略](../../config/agent-policy.json)。独立素材分析、参考分段和不互相修改的导演准备可**有界并行**；有 Script/素材/版本依赖的步骤必须等待上游结果，不能为追求速度绕开审核或冻结。

付费派发先按 provider/模型/账户限流（并发、RPM/TPM及当前价格），再原子预留 operation/generation、已有/未知费用和本轮最坏成本；排队等待不占用无用模型调用槽。请求级精确缓存和已有回执先查验，命中也核实权限、输入版本、目的与策略；不建立跨租户通用提示缓存。未知usage继续占预留，不自动重发或切换收费模型；失败后复用已成功的素材/工程/审片证据，在原限额内明确重试。

原生执行隔离、流式媒体、任务容量、缓存和输入/输出可信边界统一见[04 §3](04-architecture-and-data.md#3-队列资源与隔离)；本章只定义导演如何选择与复用结果。

## 12 检查、验收与经验

先检查项目文件、依赖、时间线、可 seek 行为、字体和资源；再看关键帧及连续帧网格；然后检查最终 MP4 的真实解码帧、帧数、时长、尺寸、音轨和事实。画面“能动”不代表“拍得好”：审阅人须在正常速度看完整片、听声音，判断产品是否清楚、有没有一段平了或无聊、阅读是否过快、相机是否无理由移动、是否存在花哨但无用的动作。

独立冷审仅拿 Brief、用户确认的事实、当前 Treatment、最终 MP4、必要参考关系和台词来源，不先看导演解释。问题必须定位时间码、可观察缺陷、严重程度及实际证据；每轮修复检查原位置与相邻窗口。静帧覆盖不等于动态、音频或美学通过；抽样与全片的结论分开。用户已接受的审美取舍无新证据不反复推翻。

质量关口失败时保留可复用产物与未解决意见；没有完整候选不得写成成功。服务端现有 Q0/Q1/Q2、输出审核、版本摘要、购买冻结和 release 的权限边界由[14](14-production-contracts.md)唯一规定，真实验收矩阵见[06](06-testing-and-release.md)。

未来的工作区创作经验必须显式开启、可查看/删除，不把私有作品自动训练成跨工作区模板。可用经验记录“题目情境→实际观察→修正→证据/信心”，新证据推翻旧经验时更新原结论，不叠一条矛盾规则。学习不改变用户已确认事实和已冻结的作品。
