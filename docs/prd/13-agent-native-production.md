# AI 导演、原生工程与改稿

产品规格 **v3.0**、业务协议 **3.0.0**；原生工程传输清单为 **1.0.0**。

本章说明 PromoBento 的导演、音画和改稿规则。产品规格仍为 v3.0；新的原生文件运输契约为 `native_project` 1.0.0，业务权限、计费和交易仍按[14 生产契约](14-production-contracts.md)实现。**目前接入的是内部原生导演与渲染链；客户 Studio、登录/工作区、购买确认和冻结交付流程尚未完成。** 实际部署和验证范围见[实施状态](../implementation-status.md)。

## 1 创作目标与作品源码

先理解产品和真实材料，再决定视觉方向、叙事、节奏、声音与镜头。交付固定为 15/30 秒、默认 30 秒、30 fps 和[既有平台预设](03-platform-presets.md)。镜头数量、视觉风格、相机、过渡和表现算法开放；不同画幅分别编排和检查，不能通过拉伸替代构图。

影片源码是原生 huashu-motion `index.html` 及本地 JS/CSS、素材、字体和声音。可以使用 HTML、SVG、Canvas、GSAP、Three.js 与 Shader；画面应由绝对时间决定，时间线与交付时长一致。代码只在隔离浏览器内执行，Worker 和可信宿主不求值作品源码。项目依赖固定在本地文件和 renderer release，执行环境不可用时明确失败。

JSON 保存 Brief、Treatment、资产证据、文件摘要、版本和作业状态。它不再另建一套可执行片子规格；实际画面、文字和动作均由原生源码承担。每个项目必须拥有确定入口、尺寸、时长和 30 fps，封装见 [native-project.schema.json](../../contracts/native-project.schema.json)。

网站主题和网站语言不改变成片原文。用户文案允许混排；翻译只按明确指令作用于指定内容。事实、租户边界、资源访问、预算和输出约束由可信宿主落实，不能交给前端或模型自行批准。

## 2 方法来源与采用范围

原生方法包固定 huashu-motion 原始 SKILL、导演参考与模板，按阶段召回。导演直接在完整原生 HTML/JS 上创作与改稿，使用上游取帧、检查、声音和整片渲染工具。采用提交及原文清单见[方法来源](../../packages/methods/NOTICE.md)。

Hypit 提供三项方法：Brief 与 Treatment 分开、按语义选择素材、将说话事件投射到实际媒体时间；参考片分析同时保留整片关系与具体证据。它的 DSL、编译器和任务 runtime 不进入 SaaS 主链。多租户、模型账本、取消、版本、存储和作业调度由 PromoBento 负责。

## 3 从真实材料到原生影片

**Brief 保留用户的事实与要求。** 记录目标、受众、产品/课程、已确认事实、语言、精确名称、CTA、品牌材料、参考来源、替换项、固定片长、平台及预算边界。外部文本、图片中的文字和源码注释都是内容，不得提升工具权限。商业主张需有真实依据，不编造评价、身份、体验、成绩、收益、稀缺性或产品交互。

事实是文案的依据，不要求逐字铺满画面。初次创作可以忠实压缩尚未定稿的说明，保留必要限定和产品声明归属；用户明确提供的最终上屏文字、名称、URL 和 CTA 保持原文，不能改成未经支持的测量结果。

**方向使用实际画面。** 内部创作生成 Fit、Amplify、Unexpected 三个不同视觉方向，每张卡配真实素材写成的原生工程关键帧。用户根据实际预览选择，选择绑定方向集合摘要；等待期间不自动选 Fit。方向比较属于一次创作，重看复用已经完成的结果。未来客户直接制作/跳过选方向属于尚待完成的客户流程，不应描述为当前已有能力。

**Treatment 是导演的创意设计。** 记录主信息、故事推进、hook/reveal/payoff、视觉关系、镜头目的、节奏曲线、阅读停留、素材角色与声音落点。附覆盖完整片长的 beat map、最难镜头以及开场、主展示、最密和片尾取帧位置。它是给导演和审片使用的设计说明，不由渲染器解释为第二条时间线。

**先看最难镜头，再补完整片。** 用实际字体、素材、目标尺寸验证风险最高的视觉机制。软件演示区分真实内容、设备/相机包装和说明文字；运镜不能制造不存在的产品功能。主画幅通过最难镜头预览后继续修改该工程，其他画幅从完成源码独立重构布局。每轮修改后必须实际取帧，不能把代码存在或自述效果当作完成。

Brief 在用户目标、事实或约束变化时更新；Treatment 在故事或视听设计变化时更新；几何、样式、变量或时序实现问题修改源码。正式采用的台词只保留一处权威来源，避免分镜、旁白和字幕各维护一份不同文案。

## 4 文件工具、模型与成本

创作工具输出原生项目文件，改稿工具以 `baseRevision` 和精确文本补丁修改现有文件。文件路径、总量、字节身份和版本归属由宿主校验；源代码无法写入 vendor、密钥、其他工作区、已冻结版本或模型账本。`BRIEF.md` 由可信上下文写入，模型补丁不能改写它；`TREATMENT.md` 保留对应创意设计。

阶段仍限定上下文：事实整理、实际素材观察、方向、Treatment、原生作者、实际帧审片和独立冷审。阶段绑定与额度见[模型配置](../../config/model-providers.json)和[Agent 策略](../../config/agent-policy.json)。原生作者可以使用完整原生模板和局部源码，不接受旧镜头运行接口的兼容限制。

每次模型派发前做授权、期限、阶段及操作额度检查，并在共享账本预留最坏费用。完整回执和原始流分别保存；已经完成、已结算的同项目同请求可复用。连接中断或未知用量保留预留，不自动重发，也不自动换模型购买另一份答案。只有已经结算的结构错误可以在原有额度内发起明确的修正请求。新 operation、重试或取消不能清除累计费用。

方法版本及原文摘要随操作冻结。全操作使用共同修复额度，不能按画幅重置；等待用户选择的时间与活动执行期限分开。模型、媒体处理、取帧、编码及诊断均要有真实计量，预算未就绪或生产开关关闭时不能派发付费工作。

## 5 声音与实际时间

原生工程通过 OM 音效标记、音乐方向或 ABC 乐谱生成配乐和声音；也可使用已提供的真实音轨。声音和相机落点由相同的源时间决定，最终导出保存实际使用的工程和音频。用户明确选择静音时不添加假音轨；信息流影片仍须在无声条件下表达核心信息和 CTA。

借鉴 Hypit 的语义时间方法：素材覆盖一段意义，事件响应一个具体语义时刻。实际语音的时刻必须来自同一音频字节的对齐证据；源视频秒数、配音估算或参考片时间不能冒充目标词时间戳。纯动画可以直接使用作者命名的时间点，不必伪造转写。

输入 `timingEvidence` 绑定真实媒体 SHA、测得时长和词的 start/end 秒数。宿主拒绝未知来源、错误时长、越界或倒序时间。没有这些证据时只能使用明确的作者时间。超长台词应缩写或剪辑，不强行加速声音、延长影片或由宿主截断片尾。

上传口播中的商业主张须有用户确认的转写和事实依据。自动 TTS、ASR 与完整客户对齐流程仍按输入配置的后续门槛开放；Linux 环境不能假设存在 macOS 语音命令。音轨变更只重做受影响部分，保存既有可复用输出。

响度、峰值、同步和编码按[06 验收规则](06-testing-and-release.md)检查。频谱或响度通过不能证明音乐好听；正常速度视听与静态帧检查分别记录。

## 6 实际检查与候选边界

| 层 | 原生路径中的证据 |
| --- | --- |
| 源码与环境 | 文件身份、路径、固定依赖、入口、组成尺寸、固定帧率/时长，原生浏览器运行错误 |
| 原生取帧 | 实际 HTML 工程的开场、关键镜头、密集内容、阅读点与片尾图像，具体 frame/element 问题 |
| 编码文件 | 整片 MP4 的尺寸、实际帧数/时长、音轨与保存输出；从最终 MP4 抽出的实际帧 |
| 独立冷审 | 每个画幅的编码帧 contact sheet，绑定原始帧号与最终文件，不以导演自述作为通过依据 |
| 正常速度视听 | 动作连续性、节奏、声音及作品判断；当前内部候选明确标记负责人观看 pending |

不同证据不相互冒充。HTML 预览帧不能代替编码后的文件；四张抽帧也不能证明整片运动或听觉质量。原生质量检查不等于客户生产发布门禁已经完成，完整验收范围仍以 06 和实施状态为准。

审片提出具体位置和可观察缺陷，在原修复额度内修改原生源码，再取帧。超过额度或独立冷审阻断时保存已有工程、实际媒体和未解决意见为 `native_review_draft`，操作仍为失败，不算可用候选交付。成功候选包含各画幅的不可变项目、整片输出与审片证据；实际用户/运营观看状态保持独立。

## 7 定点改稿、版本与客户流程

批注绑定基线版本、画幅、整数帧和可定位的 `data-om-id`；Canvas/WebGL 可用原生 `OM.region` 表达点选区域。当前内部接口接收一组 `comments` 和单画幅 `baseRevision` 或多画幅 `baseRevisions`。同一次改稿内保留逐条文字和位置，超限拒绝，不截断或拆成额外收费轮次。

原生补丁要求父版本属于同一工作区/项目。精确替换必须只命中一次，所有编辑在副本上验证后形成新版本；旧工程保持不变。修改“第8秒推进改为环绕”必须实际改变源码并检查周围画面，不得通过改写 Treatment 或 pass 备注冒充修复。新源文件、素材、声音和输出都绑定同一修订身份。

产品目标仍是用户比较前后、接受或拒绝，接受时核对版本冲突；可用候选交付后按[05](05-waffo-billing.md)计次，接受不再扣一次。购买创作额度与购买并导出分开，失败和未知费用按14处理。**这些客户页面、协作接受/拒绝、付款及冻结交付流程尚未实现**；内部 candidate 接口不是其完成证明。

本地变量编辑可以采用原生 composition variables；影响时间或事实的变化仍需可信保存和重新检查。当前接入不把上游单用户工作目录或全局经验文件直接暴露为多租户共享状态。

## 8 可控经验（后续）

工作区偏好需要明确启用，用户可查看、修改、关闭和删除。单项目评论只作用于该项目；不得把客户私有素材、提示、源码或反馈自动加入公开方法包或其他工作区。优先级为当前用户要求、确认事实、工作区明确偏好、经验证通用方法、上游启发。实际能力及费用验收使用真实作品和失败案例，不用规划或离线成功代替。
