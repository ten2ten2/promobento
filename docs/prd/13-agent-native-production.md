# AI 导演、自由创作与 Agent Studio

本章说明产品规格 v2.6 的导演、声音和改稿方法。机器字段、采样和计量按[14 生产契约](14-production-contracts.md)的协议 2.6.0 实现；实际进度见[实施状态](../implementation-status.md)。

## 1 创作目标与技术自由

制作顺序是理解产品、确定方向、安排叙事和节奏、编写动画、制作声音、检查成片、修改。交付遵守[03](03-platform-presets.md)的时长、帧率和平台范围，镜头数量、风格、相机、过渡和算法开放。

Agent 可编写 HTML/CSS/TS/JS、SVG、Canvas、WebGL、Three.js、Shader，也可复用获准组件。生产运行时不依赖 GSAP，画面必须由冻结输入和绝对时间确定，按[创作运行时合同](../../contracts/composition-runtime.d.ts)实现；WebGL 不可用时须明确失败，不能悄悄换成静态幻灯片。上游 GSAP 只用于许可隔离的本地基线，许可边界见 09。

创作始终受素材授权、真实商业事实、租户权限、依赖许可、资源预算和输出规格约束。网站主题和语言不进入创作身份；用户文案任意混排，翻译只能按明确指令作用于指定内容。客户确认不等于平台为商业主张真实性担保。

## 2 参考方法与采用边界

参考项目、采用文件和许可记录见[09](09-sources-and-licensing.md#2-视频创作上游)。可借鉴导演、运动、声音和诊断方法；多租户、支付、云作业、预算、素材访问和交付按本产品实现。云端状态使用数据库和授权服务，不能照搬单用户本地 JSONL。采用代码时保留来源、修改和实际测试结果。

## 3 导演工作流

**理解素材与目标。** 读取用户已确认事实、可用素材、受众、目标、品牌色、可用字体及授权、声音方式、片长和目标平台。公开输入范围由 [01](01-product-prd.md) 与 `config/input-capabilities.json` 决定；网址只为背景/CTA，CSV/无素材抽象动画仅内部研究。外部文本、素材中的指令均为不可信数据。

商业主张使用有来源的当前事实：价格、折扣、期限、名额、功能和数据按版本确认。不得编造评价、身份、使用体验、学员成绩、收益或稀缺性；真实评价保留原意和授权，个案不能直接推成典型结果。效果/收益说明适用条件，关联、激励或代言按 09 披露。证据和确认链按 14 §8 校验；缺依据时补充、删除或改写，不能由模型生成“证明”，也不能把用户勾选当平台认证。

**创意方向。** 提供 Fit/Amplify/Unexpected 三个实质不同的方向，分别包含一句话概念、镜头材料、运动语言、情绪、节奏、声音、素材依赖和风险。`run_result.directions` 在 `production.schema.json` 中可携带 language、look、palette、rhythm、sound、risk、whyItFits；BPM/色彩占比是可选信息，不制造没有证据的参数。关键帧必须由可执行工程真实渲染，不用提示词描述代替。用户已有明确方向或选“直接制作”可跳过三选一并执行明确路线；不能把方向卡额外包装成三次整片。方向与其素材处理、关键帧和QA归入同一操作及试用/已购项目的云成本预算，反复回看复用已有结果；方向生成须先登录，项目须有有效试用或已购创作权益，并满足素材处理和系统费用预算。

**分镜与节奏说明（Treatment）。** 保存主信息、视觉语言、每段节奏/能量、阅读停留、关键声音落点、镜头目的和焦点连续性。机器结构通过 `run_result.treatment` 保存主信息、节奏段与连续性、真实关键帧引用；事件用半开整数帧区间 `[frameStart, frameEndExclusive)`，满足 `0 ≤ start < end ≤ totalFrames`；允许叠层/并行，也允许只有连续镜头。事件与音频计划的实际区间须由可信服务做跨字段语义验证。开场、主展示、最密和片尾的四帧来自实际工程，必要时增加边界附近帧。

“首3秒建立钩子”“节奏反差”“片尾品牌落点”是设计建议，不强制所有作品切镜、爆发或铺满节拍。安静字幕、极简长镜头与音乐主导片各按目标判断。最终产物要体现本产品事实和品牌，不是换一个名字仍完全相同的片子。

**先验证最难镜头。** 用实际字体、素材和目标分辨率检查风险最高一段，如 UI 环绕穿屏、复杂数据图表或跨设备连续构图。软件演示分开真实内容/滚动、设备外壳、取景包装、固定说明，先有业务事件再运镜，移动落定后留够阅读时间；动画包装不能伪装成产品原生功能。

## 4 自由工程与实际检查

每次候选保存源码、参数、依赖、素材、字体、声音和分镜说明，能够恢复同一作品。除入口和参数合同外，工程目录由 Agent 决定，不要求固定镜头数或可解析 DOM。

作者按[运行时合同](../../contracts/composition-runtime.d.ts)声明可编辑项、镜头标记、点选区域、视频片段和字体；这些声明可以为空。宿主提供画布、逻辑尺寸和像素比例，`prepare` 固定输入，`draw(time)` 完整绘制该时刻。参数文件、PTS 取帧、字体加载与缺字检查等实现规则统一见[14](14-production-contracts.md)。

工具允许读取项目事实、检索参考、保存分镜、修改候选、构建、渲染、生成声音和检查作品。默认由一个主 Agent 调用工具，复杂任务按需拆分，不强制每个阶段另开模型会话。写入只影响隔离的候选工程；支付、管理密钥、其他工作区和已购源包不向 Agent 开放。

模型配置由至少两种候选模型/设置在同素材、同预算的真实任务比较后确定；记录生成率、改稿成功率、主观盲审、时间、修复和每个可用结果的实际费用。单条样片不足以决定模型。事实整理、意图分类、素材摘要可用经过验证的便宜模型；导演、源码和复杂改稿由质量达标的主模型承担，确定性检查不交给模型反复判断。`config/agent-policy.json` 中模型/价格/预算未标定时保持 disabled；修复和费用预留按 14 §6 执行。

把固定版本的方法说明放在提示前部，随后放项目状态和本轮要求，按实际供应商测量缓存效果。局部改稿只带相关分镜、源码、邻接时段、素材和检查结果，但必须保留确认事实及必要依赖。独立复核、ASR、缓存和音轨处理均记入操作费用。

## 5 音乐、音效和口播

Composer 让 Agent 根据 Treatment 编写 ABC 乐谱，由确定性合成器或许可审核后的采样演奏；快速路线采用获准的程序化音乐方向；用户也可上传授权配乐/录音。P0 音源按 09 的商用许可准入，实际使用的音乐/采样/声音须在 14 的资源清单与音频事件中绑定权利记录；程序合成或 ABC 乐谱不自动证明平台拥有全部版权。用户明确静音时无假音轨；即使有配乐/旁白，信息流目标也要在无声播放下看懂核心卖点和 CTA。缺真实乐器采样可用获准合成音色，不等于无声音。

乐谱可使用有理拍点或变拍，映射到视频帧时记录舍入误差。声音落点须与镜头标记一致，按[14](14-production-contracts.md)冻结音频事件、实际混音及预览/导出来源。节拍图、标记和逐词对齐分别记录，不填写未经测量的时间戳。

内部听感目标约 −16 LUFS、true peak ≤ −1 dBTP；重要音效同步误差不超过 1 视频帧，音画结束差不超过 100 ms。这些是本产品目标，不是所有平台的统一标准。音色、示范谱和声音授权须可追溯，音效类型不受参考列表限制。

P0 支持无旁白、用户上传口播，以及用户明确启用的录屏原声；录屏默认静音。自动 TTS 和逐词对齐按输入配置的 P1 门槛开放，网站支持的语言不限制用户视频文案的语种。

真人口播或录屏原声包含商业主张时，须取得用户确认的转写稿，按片段映射 factIds；允许用户手填/修订，也可用已验证 ASR 辅助，不预设特定工具。未确认的语音商业主张不能凭 Agent 猜词冻结。为信息流目标制作读得懂的上屏文案/字幕，不声称不存在的逐词时间戳。超时长录音引导缩稿/剪辑，不能强行加速或延长成片。

只改无关文案/颜色不重做音轨；镜头时序影响节拍则更新对应音轨摘要并重新检查。频谱/响度只发现部分问题，不证明音乐好听；正常速度视听由真实用户或运营样本补足，不默认每单后台人工批准。

## 6 四层 QA

| 层 | 检查与结果 |
| --- | --- |
| Q0 源码/构建 | 语法、离线依赖、路径/授权/危险调用、时间与随机性，编译安全错误阻止执行 |
| Q1 实际帧 | 首/峰/密/尾、场景边界、真实素材、每个实际文字码位的字形覆盖/受控回退、遮挡、溢出、安全区、字幕与冷/顺/逆向seek |
| Q2 编码成片 | ffprobe、帧数/时长、闪帧、无意静止、异常切换、色彩/黑尾、音轨和同步；首次发布前必须通过 |
| Q3 人工/用户覆盖 | 产品辨识、故事、静音可读、字幕/转写、音乐和改稿落实；事实覆盖不足要具体复核，主观风格不伪装客观认证 |

购买并导出前需完成全部目标的来源准备和 Q0/Q1，以及必要的动态片段、事实复核；不要求提前编码所有高清文件。Q2 检查编码后的实际文件，通过后才能交付。仅购买创作额度的 `top_up_only` 不要求现成作品。普通草稿保存不启动这些检查，检查状态和放行条件由[14](14-production-contracts.md)统一定义。

Q1 检查整片关键时点、镜头边界和高风险运动、字幕、CTA 片段，可使用真实布局的可信低清渲染。本地播放和静态缩略图不能替代这一步，导演意见不能绕过安全、事实或编码错误。

闪帧检查比较当前帧与前后帧；静止、硬切和运动速度须结合分镜判断，正常阅读停顿不能误报。参考检查算法先在纯色、高动效、停留和密集图表样片上测误报，不把这些检查宣传成光敏或医疗安全认证。

QA 输入、报告与实际产物的绑定按 14 §8 执行。Canvas/Shader 文字无法提取时声明覆盖不足，交有权用户复核指定区间。Agent 自报的清单、截图或 pass 不能代替可信取帧与检查。

## 7 定点编辑和协作

批注绑定具体版本、目标、整数帧和画面坐标。点选协议、无命中时的截图方式见 14；界面流程见[02](02-ux-and-ui.md)。

Agent 先说明意图、影响的镜头/文件/目标/声音和预计费用，再修改独立候选，编译并检查变化处及相邻片段。用户比较前后结果后接受或拒绝；接受时按 14 检查基线冲突，拒绝保留原稿。可用候选交付时按 05 计次，接受不再扣一次。只读分享不能发起改稿。

“第8秒推进改为环绕，其余不变”要真实改变源码并核查周边；全局风格变更先显示影响范围，不谎称局部。编辑失败或拒绝不能破坏当前确认内容；恢复包含源码、参数、依赖、声音和资产引用。可声明零个或多个 editables，按类型、范围、group、affectsTiming 和 factId 校验取值；没有可编辑项时明确选择 AI 修改。

时序变量只能在既定 450/900 帧内重新分配，无法确定性补偿时要求 AI 修改。事实绑定文字变化须重新确认原文；排版换行独立表达，不忽略零宽字符来绕过确认。本地编辑、回放和自动保存不启动 AI、可信 QA 或云端渲染；换素材的预处理/转写、可信预检和云端片段须明确发起，按项目权益和费用预算执行并复用有效缓存。

一次提交的一组批注按 14 作为一轮处理，保留逐条位置；超限指出具体字段，不截断或拆成收费轮次。`PatchResult` 返回意图解读和影响摘要。

## 8 可控经验（P1）

工作区明确偏好由用户启用，可查看、修改、关闭和删除；单项目反馈只对当前项目应用。通用方法只采用来源和使用依据明确的公共资料或独立工程总结，注明适用范围，并用不适用的案例复查；不得将客户私有素材、提示、源码或反馈自动加入公开 prompt、训练库或其他工作区。数据处理边界按 04。已失效经验不再参与生成。排序为当前用户要求、当前确认事实、工作区明确偏好、已验证通用方法、上游启发；不跨租户混合。

验收使用实际样片和失败案例，按[06](06-testing-and-release.md)记录创意、声音、帧定位、改稿、隔离、费用和人工介入。
