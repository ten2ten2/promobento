# 云端动效管线技术设计

对应 PRD **v3.0**、业务协议 **3.0.0**。原生工程传输使用 NativeProject **1.0.0**。本页描述当前原生实现与后续边界；实际部署和验证范围见[实施状态](../implementation-status.md)，阶段出口见 [08](../prd/08-codex-execution.md#2-里程碑与退出关口)。

## 0. 目标与边界

以完整 huashu-motion 为创作和渲染引擎，融入 Hypit 的 Brief／Treatment、真实素材证据、先解决最难镜头、语义时间和显式结果复用。固定 15/30 秒、30 fps、六个平台预设、七个业务目标、四种画幅。`targetId` 表示业务交付目标；原生工程的 composition 固定一次实际画幅，不通过拉伸代替重新构图。

不再维护 FilmSpec、积木包装、`PB.scene`、自制页面时钟或跨容器分片拼接。网站、认证、支付、客户实时预览和素材服务仍按各 PRD 实施，不能把内部 API 当作已开放 SaaS。

## 1. 设计目标

### 1.1 单位成本

数值以 [agent-policy.unitCostTargets](../../config/agent-policy.json) 为准；范围和核算方法见 [07](../prd/07-growth-and-experiments.md#4-完整单位经济)。创作包含素材理解、方向、自写镜头、审片、全部内部修复和主画幅成片；改稿和目标准备包含其必要 QA／失败费用。计算费、模型费和未知预留分开报告，不能用单文件编码费替代完整操作成本。

止损上限不是成本目标。S1 的创作模型 p50 ≤$0.70、p95 ≤$1.20，完整阶段使用配置中的目标。超标先优化有效缓存、上下文、局部编辑与已验证模型路由；仍不达标由负责人决定目标、价格或权益，不在实现中自行缩减。

### 1.2 时间

除明确标注外为 p50 目标；实际分布包含失败及完整墙钟，不能删掉排队或混合不同资源候选。

| 环节 | 目标 |
| --- | --- |
| 开始创作至三张真实方向卡 | ≤2 分钟 |
| 选方向至可播放原生草稿 | ≤3 分钟 |
| 选方向至完整候选（含自写、审片、成片与 QA） | ≤10 分钟；p95 ≤18 分钟 |
| 定点改稿至候选 | ≤3 分钟 |
| 已准备项目的原生取帧 | ≤3 秒 |
| 30 秒低清 review 与发现 | ≤30 秒 |
| 纯 2D 最终片 | 30 秒片 ≤60 秒；15 秒片 ≤45 秒 |
| WebGL 最终片 | 帧占比 ≤30% 时 ≤180 秒；整片 3D ≤300 秒 |
| 准备四画幅，纯 2D | ≤3 分钟 |

产品完整构图处理另保留p95门槛：standard空队列单30秒构图≤5分钟、常用三构图批次≤12分钟，从实例准备至必需检查完成；排队／传输另报，批次按实际调度测量，不能将单片耗时乘三。S1客户端墙钟仍包含排队，不能混用计时口径。

硬期限见 §5，不作为性能达标值。当前性能结果见[性能证据](../evidence/2026-10-24-s1-performance/README.md)，不把旧资源的分布当成当前配置。

### 1.3 质量与安全

质量目标仍为 S1 负责人正常速度视听愿意发布不少于 4/6，完整阶段不少于 5/6。静帧、模型判断与编码通过各有适用范围，不能替代正常速度播放与听觉验收。旧引擎的性能、隔离与作品结果不自动适用于新运行时。

## 2. 总体架构

Cloudflare Workers 提供内部任务与版本入口，OperationWorkflow 编排导演及方向等待，RenderWorkflow 编排一个原生预览或整片任务。D1 保存任务、不可变版本关系及计算账本；独立 MODEL_LEDGER 保留跨环境模型成本和未知预留；R2 保存输入、实际工程、媒体和证据；Queues 投递事务 outbox。

CoordinatorDO 控制实例 lease。为保留已部署 Durable Object 的存储身份和物理停止／结算句柄，绑定名 `SHARDS` 和类名 `ShardDO` 暂保留；其新执行逻辑只有 `preview`／`export`，不再规划分片。一个任务一台容器，完成或失败后确认物理停止再归还容量。

### 3.2 完整上游与发布锁定

完整上游固定为 `52467f99c602b76ba86d511d37acdfe93fa1e16e`（v0.3.1），Docker 构建核对 [315 个 blob 的锁](../../packages/native-motion/upstream.lock.json)，保留 CLI、Studio、runtime、templates、fonts、examples、skills。服务执行采用隔离适配器；上游 localhost Studio 不能直接暴露成多租户服务。

镜像只在 GitHub Actions 构建／推送。Node、Chrome、FFmpeg 和固定上游版本均进入环境锁。新 release 不覆盖旧镜像记录；仍被旧任务或历史交付引用的环境和数据继续保留。

## 4. 原生项目与改稿

项目由 `index.html`、本地 JS/CSS、assets、vendor 组成。NativeProject 清单只负责路径、不可变 BlobRef、runtime pin 和 composition；HTML／原生 timeline 才是画面本体。容器补齐固定内置库，校验根尺寸、时长、帧率及实际浏览器信息，不替作者自动拉伸、补时或截断不符规格的作品。

版本经 `baseRevision` 约束，修改产生新工程和新 hash。Brief 的确认事实保持独立；视觉修正编辑原文件，故事改动同步 Treatment，改变事实必须走事实确认。每个画幅单独创作并审片。项目中可用的资源来自已准入的不可变文件；不允许模型安装 npm 依赖或把源码放进可信 Node／Worker 求值。

## 5. 预览与整片执行

`preview` 使用原生 capture，默认取 0、1/3、2/3 和最后一帧，可指定最多十二个合法时刻。`export` 使用原生整片 renderer、声音准备和混音，初期固定一个 browser worker；同一任务内由可信 FFmpeg 归一交付编码，然后核对 450／900 帧、PTS、尺寸、编码、色彩、音轨、大小与码率。

导出同时保存实际工程全文件和 rendered-project manifest，分别记录输入 source hash、实际 HTML hash、实际工程 hash。F 冷审看到最终 MP4 解码帧和接触表；HTML 预览帧不能冒充已编码成片证据。声音听感和完整动态审核仍需独立验收。

初始调度限制由 `nativeRenderPolicy` 给出：standard-3、全局四实例、同工作区一实例，预览三分钟／导出十分钟硬期限。这些是止损，不是实测 SLA。未知计算费用或未确认停止阻止新 attempt；仅已停止且已结算的可恢复平台故障允许有限重试，不重复已成功的模型响应。

## 6. 原生导演

事实／素材理解 → 三个真实原生方向预览 → 持久化等待选择 → Brief／Treatment → 最难镜头试片 → 原文件补全 → 实际预览与精确改稿 → 各画幅整片导出 → 实际编码帧冷审 → 候选或保留失败草稿。模型阶段与预算见配置；完整控制面入口见 [cloud README](../../apps/cloud/README.md)。

模型原始回执、实际 usage、未知预留及累计止损仍由现有账本管理。方法变更不重置活动时钟或预算，不给未知请求自动换模型重发。新付费试跑必须有当前有效授权。

## 7. SaaS 与隔离边界

源码仅在无凭据的 Chromium 沙箱内执行，控制器与原生子进程分 UID；容器禁公网，broker 仅允许任务输入读取和指定输出写入。路径、symlink、真实字节和媒体源路径均由宿主验证，取消或超时最终由控制面确认整个容器停止。浏览器攻击语料、跨任务残留和真实 Cloudflare 停止仍需对应环境验收。

客户预览应采用独立 origin／sandbox iframe，使用同一冻结工程和原生播放器；用户实时编辑、点选、评论 UI、租户 ACL、Google／邮箱与 Waffo 尚未实现。内部管理令牌的 R2 准入不能替代客户资产权限。

## 10. 安全、可观测与验收

### 10.1 验证范围

离线契约测试验证路径、hash、不可变改稿、真实编排、账本与恢复；Docker 原生烟测验证四画幅、原生变量编辑、GSAP／WebGL 和 15/30 秒有声整片。CI 不调用模型或部署云资源。通过媒体测试仍不能宣称任意源码隔离或真实作品质量通过。

### 10.2 G1 云端检查点

在固定预发布镜像补验真实 broker／R2／D1、Cloudflare 容器能力、完整 2D 与 WebGL 性能分布、并发、取消／原生终止／restart 防重放、物理回收及费用结算。旧分片接缝矩阵不再用于新引擎；按原生引擎的实际风险检查 seek、视频、字体与完整编码。性能目标、预算和质量出口保持，未测内存继续按既有平台限制留待实际数据补验。
