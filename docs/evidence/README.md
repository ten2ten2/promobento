# 关键验收记录

此目录保存有长期审阅价值的实际验收：外部集成、人工验收、性能与成本、故障恢复，以及影响结果解释的重要环境发现。**不要求每次改动新增 evidence。**

日常静态检查、构建和可重复测试的结果随提交说明或已有 CI 报告；重复回归场景由实际测试脚本维护。当前仓库尚未建立 CI，不能把本地检查写成 CI 已通过。完成情况和阻塞项见 [实施进度](../implementation-status.md)，选型与取舍见 [实施决策](../implementation-decisions.md)，本目录不复制这两处的内容。

## 记录什么

关键记录写清五项即可：**被测版本、环境、执行方法、结果与适用范围、原始结果的位置**。方法可引用可复用脚本或说明必要的人工步骤；结果包括失败项或尚未验证的部分。原始结果未留存时明确写明，不把一段检查摘要描述成可复跑的测试套件或已归档的产物。

被测仓库内容用提交版本定位即可，无需重复列普通 HTML、模板和源码的长串 hash。镜像 digest、被测视频或二进制的完整性标识在确有定位需要时保留。不要为一次常规检查再复制消息键数、文档数或完整命令输出。

## 后续应用证据

M0–M4 继续按 [测试与发布要求](../prd/06-testing-and-release.md) 保留关键验收，例如 Cloudflare 渲染、Waffo 验签与退款、权益并发、两类用户流程和平台上传。文件名包含日期与用途；通过测试输出、脱敏日志、样片或受控产物位置支持结论。减少日常记账不降低真实集成和生产发布门槛。

不把私钥、访问令牌、带授权的下载地址、真实客户素材或完整付款个人信息提交到证据目录。可引用受控环境中的脱敏记录；需要审阅的可公开样片在取得素材授权后再纳入。
